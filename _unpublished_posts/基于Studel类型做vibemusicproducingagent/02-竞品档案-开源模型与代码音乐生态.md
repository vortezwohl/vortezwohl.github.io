# 02 · 竞品档案 · 开源模型与代码音乐生态（Strudel 生态深档）

> 数据时点: 2026-11-05。Codeberg/GitHub/HN 为当日浏览器实测；学术论文经 arXiv HTML 实读。

## 1. Strudel 本体（本 idea 的交互底座）

### 1.1 项目现状【事实】(codeberg.org/uzu/strudel 实测 + strudel.cc 可达性复验)

- 仓库已迁至 **Codeberg（uzu/strudel）**: 1.3k star / 367 fork / 6,632 commits / 407 议题 / 144 PR / 20 releases；yaxu（Alex McLean，TidalCycles 创始人）近期仍在提交。定位: "Web-based environment for live coding algorithmic patterns, a faithful port of TidalCycles to JavaScript"。AGPL。
- strudel.cc（Strudel REPL）本轮实测**可达**（上一轮 2026-10-29 调研时该域名不可达，网络环境已变化）。Safari 兼容仍差（HN 用户: "Sadly doesn't even run at all on safari"）。
- r/strudel 子版独立存在且日更活跃（音乐分享+语法求助型社区）；TidalCycles 社区部分并存。
- 周边编辑器生态: strudel.nvim（浏览器+nvim 同步）、Rustel（见下）、Stave（见下）、flok（实时协作 live coding 平台，用户情感锚点: "I like collaborating with randos on flok"）。

### 1.2 官方 "post-ai humane policy"（决定性约束）【事实】(r/strudel 政策帖全量精读)

- 2026-10-25 由 yaxu 发布（99分/66评），全文见 codeberg.org/uzu/strudel POLICY.md。要点:
  - 贡献含 LLM 生成内容 → **拒绝**；LLM 生成的 commit/issue/论坛文本 → 标记并删除；
  - "LLM-based scraping and generation of (A)GPL code ... is of questionable legality ... LLM-generated work does not have a copyright holder and can therefore not be licensed under the (A)GPL"（官方法律论点）；
  - "We strongly discourage others from forking/importing our projects into corporate AI platforms, including Microsoft Github."（并已带头迁出 GitHub）；
  - **豁免条款**: "A contributor's personal use of LLMs and related technology is their own business, whether for research, analysis, bug discovery or other assistive technology, so long as the output is not included in any contributions to our projects."
  - yaxu 澄清: "We just want to interact with human code while working on strudel."
- 社区反应: 压倒性支持；少数派质疑被踩沉。评论中出现不打算遵守的 fork（"Dexter" Windows 桌面移植: "Like I am going to unfork it"）。
- **边界结论**: agent 为"用户个人创作"生成 Strudel pattern = 政策明文允许；把 Strudel 源码吞进闭源商业 AI 产品 = 社区敌意+官方认定的法律灰色区。合规路线有三: (a) agent 作为"外部编辑器/副驾"调用 Strudel（不 fork 不嵌引擎）；(b) 自研兼容 mini-notation 的引擎；(c) 开源整体产品满足 AGPL。【推断+事实组合】

### 1.3 Strudel 用户的真实痛点与自发 LLM 行为【事实】(HN 563 分帖 + r/strudel 求助帖)

- 文档 incomplete（"only chapter 1 is done out of what ultimately will/should be a 25 chapter tome"）→ 用户自发 "ask an LLM to make a line of whatever: a beat, a synth, etc., tweak it, then layer it"；
- 乐理映射断裂: "every single piece of its interface seems determined to confuse people who already know music theory... wish there was a way... mapped back to traditional music notation, especially rhythm notation"；
- 求助帖主题（r/strudel 近期）: cps 导出不生效、失真渐变、dynamic pattern、基础语法——调试/概念门槛是高频摩擦；
- 表演破圈: "more and more strudel musicians doing a kind of live coding performance art and posting clips on tiktok and reels. It's really entertaining"——短视频平台是 natural growth channel；
- 学习动机为真实情绪价值: "digital dopamine"、"I get more motivated when I can see it working directly and change some code here and there!"

## 2. Strudel 生态新工具（2026-10~11 窗口，竞品/互补品并存）

### 2.1 Rustel（Rust 原生引擎，2026-11-03 发布，65分/23评）【事实】

- "99% strudel feature complete"；终端 studio（live editing/piano roll/scope/spectrum/mixer、Vim 模式、auto-evaluate）；CLI: `rustel play --watch yourScore.strudel`；支持 VST3/Ableton Link/OSC/MIDI/stems 导出/"session tapes（nothing you play is ever lost）"；AGPL；rustel.cc。
- **对本项目的意义**: CLI+watch 模式 = 天然的 agent 执行后端（LLM 写文件→自动重评估→出声）；stems 导出=与 DAW 工作流衔接的接口。评论区唯一顾虑: 采样版权（作者已逐个核验并文档化）。

### 2.2 Stave（Strudel 的"制作人 GUI"层，2026-10-24 beta）【事实】

- "keeps your Strudel code as the source of truth and adds the views a producer expects: Timeline / step grid / piano roll / Mixer"；monaco 编辑器；p5/Hydra/GLSL 可视化经 `.viz()` 挂载；代码↔视图**双向写回**；AGPL；stave.live。
- r/strudel 接受度（61分/24评全量精读）: 核心反对= "the whole point of strudel is making your beats from code, doing it with the ui kinda defeats the purpose"；技术批评=双向转换覆盖不全、紧凑 mini-notation 膨胀 4 倍、'#' 升降号 bug；"vibe coded"成为审查问题（作者最终坦承 "fully AI coded" 并以技术实质+真诚化解最激烈反对者）。
- **对本项目的意义**: "代码为真源+GUI 视图"已被验证可行且会被社区审查 AI 成分——披露策略必须前置。

### 2.3 loopmaster.xyz（code-music×vibe coding 的直接先行者）【事实】

- HN 260 分帖（2025-12 "How to Synthesize a House Loop"）主角；教学驱动（手写代码合成 house loop）；**带 `/generate` 页面=内置 LLM 生成 loop 程序**（HN 用户: "it has built-in vibe coding, to produce an LLM-generated loop program to start one's creative journey"）。
- HN 评论金句: "I really want something like this as a VST plugin... it would be a great instrument to have"（code-music 的期望形态=乐器而非整曲机器）；"What's going on with all these code-2-music tools these days?... is there a rising trend?"（2025-12 已被感知为趋势）；开源期望（"want the ability to understand and modify any part of the stack, it's the nature of the audience"）；信任信号（无 landing/About 页被指 red flag）。
- 边界诚实记录: 制作向用户的采纳门槛也出现在同帖——"it's not clear to me what they can add to my production repertoire compared to the existing tools"。

### 2.4 其他生态坐标【事实】

- dittytoy.net（JS 音乐编程玩具）、ChucK（普林斯顿）、Sonic Pi、FoxDot、Glicol（14号报告存量）；

## 3. 开源生成模型（agent 的"渲染器"选项）

### 3.1 YuE2（multimodal-art-projection/YuE）【事实】

- 13.1k★ / 1.5k fork；活跃（新闻至 2026-10）。
- 架构: **符号规划→音频渲染两阶段**——先生成**可编辑的旋律与和弦谱（ABC notation）**，再渲染 48kHz 立体声全曲；支持零样本翻唱（SheetSage2 转谱重唱）；README 明确提及"智能体化的乐谱编辑"；WildSongBench 评测。
- License: 代码 Apache 2.0；**权重 CC BY-NC 4.0**（个人可商用其生成内容；公司商用需另行授权）。
- ★架构启示: "agent 可编辑的符号层 + 渲染器"与 Strudel-agent 范式同构；ABC/mini-notation 就是现成的 agent 编辑接口。

### 3.2 ACE-Step（ace-step/ACE-Step）【事实】

- 5.0k★ / 656 fork；v1.5（2026-01）；**Apache 2.0（含权重，商业可用）**；4 分钟生成约 20s（A100）；19 语言；操作面含 Text2Music/Retake/**Repainting/Edit/Extend**/Remix/歌词编辑；LoRA（Lyric2Vocal/Text2Samples/RapMachine）；Roadmap 有 ControlNet 类 StemGen（单轨生成）。
- ★定位: 本地部署+合规商用的首选开源渲染器；"局部编辑"接口已内建。

### 3.3 其他【事实】

- MiniMax Music 2.0（2025-10-31）: 闭源权重但发布时引发 529 分讨论；r/SunoAI 用户实测评价"quality and adherence of output is the best in open weights, but lacks variability and customisability"；2026-08 API 收缩。
- HeartMuLa（seed hunting 用）"not as final"；社区在等 Qwen 音乐模型（"some impressive research papers... gonna be insane"）。
- Magenta.js 生态: 主库 2026-01 归档但子仓库延续维护（14号报告存量事实）——浏览器端推理（MIDI/符号层）仍可用，与 Strudel（浏览器）同域。

## 4. 学术坐标【事实】

- arXiv 2602.05064（CHI 2026）"A Design Space for Live Music Agents": **184 系统**分析、31 维度、四 aspect（Usage Context / Interaction / Technology / Ecosystem）；代表案例 jam_bot（与 Jordan Rudess 人机即兴）、Shimon（机器人马林巴）、ReaLchords（实时和弦伴奏）、Channel-AI（混音助手）。→ "live music agent"已是有 184 个样本的正式研究领域，但**尚无消费级产品赢家**。
- CHI 2026 引文 "AI Jam Session: Vibe-Coding meets Live-Coding Music with Emergentic.ai in Strudel"——学术侧已把 Strudel 当作 vibe-coding×live-coding 的汇合点（Emergentic.ai 官网现为多智能体模拟平台，音乐项目疑为副线/已转型——**未获一手确认**）。
- 西语论文（2026-06）把 Strudel 定位为 "prescriptive notation"（规定性记谱）——概念上支撑"代码即乐谱、agent 即改谱人"的产品叙事。

## 5. 小结

代码音乐生态的三个事实叠加构成了本 idea 的机会底盘:
1. **引擎成熟且免费**（Strudel/Rustel，AGPL，浏览器/CLI 可达）；
2. **渲染器可选且许可可控**（ACE-Step Apache / YuE2 NC+授权 / 商用 API）；
3. **用户行为已经先行**（用 LLM 写 pattern、vibe coding 功能出现在独立工具、HN/TikTok 传播）——产品要做的是把自发行为产品化，而不是教育市场。【推断】
