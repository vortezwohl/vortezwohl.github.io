## 一、面试全局框架：这轮面试到底在考什么

### 1.1 一句话结论

> 面试官最关心的不是"你懂多少名词"，而是：**你能不能把一个模糊的业务治理问题，拆成可验证的模型/数据/流程动作，并且在准召、成本和业务体验之间做出可解释的取舍。**

任何回答都要能闭环到四个词：

| 关键词 | 含义 | 面试官想听到的 |
| --- | --- | --- |
| **准召** | Precision / Recall / F1 / 阈值 / 混淆矩阵 | 你说"准确率 91.4%"，还是"高置信区间 Precision 98%、Recall 85%，工作点选在误杀率 0.3% 处" |
| **ROI** | 人工审核成本、GPU/API 成本、延迟、误杀的业务损失 | 你敢不敢说"这个方案我不上，因为成本增幅大于收益" |
| **闭环** | badcase → 归因 → 数据/SFT/RL/策略 → 评测 → 上线 → 监控 | 你讲的是"一次性 demo"还是"可持续迭代的链路" |
| **可验证** | 指标口径、AB 实验、离线 vs 线上、置信度 | 你的结论有没有对照组、护栏指标、置信区间 |

### 1.2 面试官人设与评分逻辑

| 评分维度 | 权重感 | 面试官在找什么 |
| --- | --- | --- |
| 项目真实性 | 25% | 动机、数据、基线、误差、失败样本是否讲得清 |
| 业务判断力 | 20% | "为什么这样做 ROI 更优"能否自洽 |
| 技术深度 | 20% | SFT/RL/RAG/Agent 是懂原理与失效模式，还是只会调包 |
| 工程闭环 | 15% | 从数据到监控的完整链路，而非一次性 demo |
| 沟通与反应 | 10% | 被追问时不慌乱、不甩锅、会承认未知 |
| 价值观/适配 | 10% | 对内容安全、人审协作、高压应急的理解 |

**刻薄面试官的典型开场**：

> "你简历写得很满，但全是生成、翻译、网文。我们这边是广告、电商、生活服务的机审，你哪段经历能证明你会做风控和误杀权衡？"

这句话不是要你认输，而是测试你的**迁移能力**。正确接法三连：

1. **先承认差异**（不辩解）："您说得对，我没有商业机审的直接经验。"
2. **再给出可复用方法论**："但我在剧本审核项目里已经跑通了'规则 + 多模型投票 + 人审兜底 + badcase 回流'的完整闭环，这本质上就是一个缩小版的机审系统；我的 SFT/DPO 数据构造、多模型不一致消解、小样本评测方法论可以直接迁移。"
3. **最后落到岗位诉求**："如果给我这个岗位，前三个月我会先把'准召口径 + 阈值路由 + badcase 归因'这三点立起来。"

### 1.5 项目深挖的十条满分逻辑

面试官对项目的追问只围绕一件事：**真实性与闭环**。用下面十条自检：

1. **Q1 项目介绍**：用"问题 → 数据 → 模型 → 指标 → 失败 → 闭环"六段式讲，每段不超过两句话。
2. **Q2 DPO 数据怎么构造**：chosen/rejected 必须讲清"噪声控制"——同 prompt 多版本生成、人工排序、规则过滤、去重去模板、交叉审核一致性（Kappa）。这是你区别于"调包选手"的关键。
3. **Q3 多模型投票不一致**：给出具体消解策略——置信度加权、投票阈值、分歧样本转人工、二次大模型仲裁；并给出"不一致率"这个监控指标。
4. **Q4 为什么用 BERT + Bi-LSTM + ElasticNet 不用大模型**：成本（高 QPS）、延迟、可解释性（申诉要能讲理由）、稳定可控；大模型做低置信复核。这正是机审的"大小模型分层"思想。
5. **Q5 300 条样本 91.4% 可不可信**：诚实回答"不可直接信"——样本量小、置信区间宽（可用 Wilson 区间估算）、需分组交叉验证、需人工抽检一致性；给出扩大标注 + 主动学习的计划。**不要嘴硬**。
6. **Q6 翻译修改率 4.5%**：只能说明"机器初译质量较高"，不能直接推出成本下降；要补人审抽样误改率、漏改率，才能算 ROI。
7. **Q7 800 章长篇连贯性**：讲长文本建模——chunking/overlapping、记忆/摘要、世界观知识库（RAG）、关键设定约束生成、前后一致性校验。
8. **Q8 Autono / EasyHarness**：讲清解决的问题——Agent 的可靠执行与统一评测；与 JD Harness 的关系——"Harness = 模型/策略的统一评测与实验框架，EasyHarness 就是我在这个方向的实践"。
9. **Q9 最大失败案例**：真实失败 + 归因 + 修复闭环（例如"准确率高但漏杀严重→发现是类别不平衡+阈值问题→改阈值与数据配比"）。失败案例的含金量在于你讲不讲得出归因。
10. **Q10 剧本审核改造成真机审系统**：加什么——业务上下文特征（作者/账号历史）、规则前置层、置信度双阈值路由、人审回流、线上监控与 AB、申诉通道。答案直接复用第七部分的机审全链路。



## 二、Python 语言基础（对标 Q11–Q22，Peer 面必考）

> 学习目标：Peer 面问 Python 不是为了考语法，而是看你对"运行时行为"的理解深度。所有题都要能从"内存模型 / 执行模型"推导出答案，而不是背结论。

### 2.1 可变对象 vs 不可变对象（Q11、Q13 的根）

**是什么**

- 不可变（immutable）：`int`、`float`、`str`、`tuple`、`frozenset`、`bytes`。任何"修改"都是生成新对象。
- 可变（mutable）：`list`、`dict`、`set`、`bytearray`。修改发生在原地。

**为什么（内存模型）**

Python 变量是"名字 → 对象的引用"。`a = [1, 2]` 是把名字 `a` 绑定到列表对象；`b = a` 是让 `b` 也指向同一对象。判断两个名字是否指向同一对象要用 `is`（比较对象地址），判断值是否相等用 `==`（调用 `__eq__`）。

```python
a = [1, 2]
b = a          # b 和 a 指向同一个 list
c = a[:]       # 切片产生新 list（浅拷贝）
a.append(3)
print(b)       # [1, 2, 3]，b 跟着变
print(c)       # [1, 2]，c 不受影响
```

**面试怎么答（Q13 函数默认参数陷阱）**

> "Python 函数默认参数在**定义时只求值一次**，保存的是同一个对象。如果默认值是可变对象，多次调用会共享它，导致状态污染。"

```python
def f(x, cache=[]):   # 错误示范：默认列表跨调用共享
    cache.append(x)
    return cache

def f(x, cache=None):  # 正确做法：用 None 哨兵，函数内再创建
    if cache is None:
        cache = []
    cache.append(x)
    return cache
```

**追问**：

- `tuple` 真的不可变吗？→ 元组本身不可变，但元组里的元素若是可变对象（如 `t = ([1], 2)`），`t[0].append(3)` 可以成功。不可变是"引用集合"层面的。
- `is` 判断 `a == 1` 用哪个？→ 数字、短字符串有驻留（interning）优化，`is` 结果不可靠，**判断值必须用 `==`**；只有 `x is None` 这种单例判断才用 `is`。

### 2.2 四大容器：list / tuple / dict / set（Q11）

**面试怎么答（先说实现，再说选型）**

| 容器 | 底层实现 | 插入/查找复杂度 | 特点与场景 |
| --- | --- | --- | --- |
| `list` | 动态数组（连续内存 + 扩容） | 尾部追加均摊 O(1)；按下标 O(1)；按值查找 O(n) | 有序、可重复、允许切片；高频尾部操作 |
| `tuple` | 定长数组 | 同 list | 不可变、可哈希，可作 dict 的 key；数据天然不该变时用 |
| `dict` | 哈希表 | 均摊 O(1) | key 唯一、有序（Python 3.7+ 保插入序）；查重、映射、计数 |
| `set` | 哈希表（只有 key） | 均摊 O(1) | 去重、集合运算（交集/并集/差集） |

**为什么 dict/set 是 O(1)**：哈希表把 key 经过哈希函数映射到桶，冲突用开放寻址或链地址解决。均摊 O(1) 的前提是 key 可哈希且哈希均匀；最坏情况（大量哈希冲突）退化 O(n)。

**易错点**：

- `dict` 的 key 必须是**可哈希**的 → 可变对象不能当 key；`list` 转 `tuple` 后才能当 key。
- `set` 与 `dict` 的查找比 `list` 快，LeetCode 去重/查存在一律优先用它们。
- 需要有序 + 去重 + O(1) 操作？Python 没有内置，可用 `dict.fromkeys` 保序去重：

```python
def dedup_keep_order(xs):
    return list(dict.fromkeys(xs))   # dict 保插入序，值取默认 None
```

### 2.3 深拷贝 vs 浅拷贝（Q15）

**为什么需要区分**：`=` 只复制引用；拷贝是为了得到独立对象。但对象里嵌套的对象怎么办？这就是深浅拷贝的分界。

```python
import copy

a = [[1, 2], [3, 4]]
b = copy.copy(a)      # 浅拷贝：新建外层 list，内层子 list 仍共享
c = copy.deepcopy(a)  # 深拷贝：递归复制所有层级

b[0].append(9)        # a[0] 也会变成 [1, 2, 9]
c[0].append(8)        # a 不受影响
```

**面试怎么答**：浅拷贝只复制顶层；深拷贝递归复制所有层级。选择规则：能浅拷贝就不深拷贝（深拷贝慢且可能递归失败）；业务上需要完全隔离才用 `deepcopy`。

**追问**：怎么判断一个对象是否可变？→ 一般"可哈希"（有 `__hash__`）暗示不可变；更可靠的是看类型语义与文档约定。

### 2.4 GIL 与并发选型：多线程 / 多进程 / 协程（Q14、Q22）

**GIL 是什么**：CPython 解释器用一个全局锁保证同一时刻只有一个线程执行 Python 字节码。**为什么要有 GIL**：简化内存管理——CPython 的引用计数不是线程安全的，有了 GIL 就不需要为每个对象加锁；代价是纯计算多线程无法利用多核。

**关键区分：IO 密集 vs CPU 密集**

| 场景 | 选型 | 原因 |
| --- | --- | --- |
| IO 密集（网络、磁盘、HTTP 调用） | 多线程 / 协程 | IO 等待时会释放 GIL，线程在等待期间不占 CPU，可以用并发掩盖延迟 |
| CPU 密集（矩阵计算、循环） | 多进程 | GIL 导致多线程只能跑满一个核；多进程各解释器独立，能利用多核 |
| 超大规模并发 IO | 协程（asyncio） | 单线程 + 事件循环，上下文切换开销最小，可支撑十万级连接 |

**为什么 IO 密集多线程有效**：GIL 在遇到阻塞 IO 时会被释放，其他线程趁机执行；对纯 Python 计算，GIL 每执行若干字节码就切换，反而有调度开销。`time.sleep`、`requests`、数据库驱动等都会释放 GIL。

**面试怎么答（Q22）**：

> "选型看瓶颈：IO 密集用多线程或协程，CPU 密集用多进程。多线程有 GIL 限制但写法简单；协程切换成本最低但不适合 CPU 计算和阻塞型同步库；多进程隔离最好但进程间通信和内存开销大。"

**追问**：

- GIL 会被移除吗？→ PEP 554 / Python 3.13 的 free-threading（no-GIL）构建在演进，但生态兼容仍是难题；默认 CPython 仍有 GIL。
- `numpy`/PyTorch 为什么能多线程加速？→ 底层 C/CUDA 代码释放 GIL，在原生代码里并行。
- asyncio 里调用阻塞函数会怎样？→ 会卡住整个事件循环；应把阻塞调用丢给线程池 `asyncio.to_thread`。

### 2.5 迭代器、生成器与协程（Q16、Q19）

**是什么**

- 迭代器（iterator）：实现 `__iter__` 和 `__next__` 的对象，`for` 循环的本质是不断调用 `next()` 直到 `StopIteration`。
- 生成器（generator）：用 `yield` 的函数，调用时返回生成器对象，执行是惰性的——`yield` 暂停，`next()` 恢复。

```python
def gen(n):
    for i in range(n):
        yield i * i          # 暂停并吐出 i*i

g = gen(3)
print(next(g))  # 0
print(next(g))  # 1
```

**为什么生成器省内存**：普通列表会一次性分配全部元素；生成器每次只产生一个值，**边算边吐**，不保存中间序列。处理大文件/大流就是靠这个。

**面试怎么答（Q16）**：

> "迭代器是惰性取值的迭代协议；生成器是迭代器的一种便捷实现。优势有三：省内存（不一次性构造序列）、支持无限流、可以组合管道（如 `itertools`）。"

**追问**：

- 生成器能 `len()` 吗？→ 不能，它是流，不知道长度；想知道只能 `sum(1 for _ in g)` 或先转 list。
- 生成器函数与 `yield from`？→ `yield from sub` 把子迭代器的产出逐个转发，用于扁平化嵌套。
- 生成器和协程的关系？→ `yield` 同时是"接收值"的通道：`g.send(value)` 可以把值送回生成器内部，这是 asyncio 协程的底层机制。


### 2.6 闭包、装饰器、*args / **kwargs（Q17、Q18、Q21）

**闭包是什么**：内层函数引用了外层函数的局部变量，且外层函数返回后这些变量仍被内层函数持有（保存在函数对象的 `__closure__` 里）。**为什么有用**：可以在不污染全局的前提下"记住状态"，是装饰器、回调、偏函数的基础。

```python
def counter():
    n = 0
    def inc():
        nonlocal n      # 注意：需要 nonlocal 才能修改外层变量
        n += 1
        return n
    return inc
```

**装饰器**：接收函数并返回新函数的可调用对象，本质是语法糖 `@deco` 等价于 `f = deco(f)`。

```python
import functools

def logged(func):
    @functools.wraps(func)          # 保留原函数的 __name__/__doc__
    def wrapper(*args, **kwargs):
        print("call", func.__name__)
        return func(*args, **kwargs)
    return wrapper

# 带参数的装饰器：多套一层工厂函数
def repeat(times=3):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for _ in range(times):
                func(*args, **kwargs)
        return wrapper
    return decorator
```

**面试怎么答（Q17）**：装饰器 = 不修改原函数代码的前提下给函数加行为；典型应用是日志、计时、鉴权、缓存（`lru_cache` 本质也是装饰器）。**为什么必须 `functools.wraps`**：否则被装饰函数的元信息被 wrapper 覆盖，调试和文档工具会错乱。

**Q18 *args/**kwargs**：`*args` 收集位置参数为 tuple，`**kwargs` 收集关键字参数为 dict。解包时反向使用：`f(*list_, **dict_)`。

**追问**：

- 装饰器可以用于类吗？→ 可以装饰类（返回新类），也有 `classmethod`/`staticmethod`/`property` 这类内置装饰器。
- 闭包和全局变量区别？→ 闭包变量的作用域限定在外层函数，避免全局污染；多个实例各自持有状态（类似"私有状态"）。
- `nonlocal` vs `global`？→ 修改外层函数变量用 `nonlocal`，修改模块级用 `global`。

### 2.7 异常处理与 finally（Q20）

**核心知识点**：

- `try/except/else/finally` 的完整语义：`else` 在无异常时执行；`finally` **无论是否异常、是否 return，都会执行**（除非进程被强杀）。
- `finally` 里不要 return：`finally` 的 return 会覆盖 try 里的 return，是常见坑。
- 异常是"错误对象沿调用栈向上传播"，捕获要按具体类型，不要裸 `except:` 吞掉所有错误。

```python
def read(path):
    try:
        with open(path, encoding="utf-8") as f:   # with 自动调 __exit__，保证关闭
            return f.read()
    except FileNotFoundError:
        return None
    except OSError as e:
        raise RuntimeError("读取失败") from e     # 链式异常保留根因
    finally:
        print("无论如何都会执行")
```

**面试怎么答（Q20）**：`finally` 用于释放资源（关闭文件、释放锁）这类"必须执行"的逻辑；上下文管理器（`with`）是资源管理的现代写法，等价于 `try/finally` 的封装。

### 2.8 大文件处理（Q19）

**核心原则：不要一次性 `read()` 进内存，要用迭代/分块/流式。**

```python
# 逐行迭代：readline 惰性读取，一行只占一行内存
with open("big.log", encoding="utf-8") as f:
    for line in f:
        process(line)

# 按块读取（二进制/超大单行文件）
with open("big.bin", "rb") as f:
    while chunk := f.read(1024 * 1024):   # 海象运算符，每次 1MB
        process(chunk)
```

**面试怎么答**：大文件处理三原则——用迭代器/生成器惰性读取；用 `with` 保证资源释放；必要时分块 + 多进程/流式聚合。若单机内存不足，考虑分片、外排或上 Spark/Flink。

**追问**：进程内读 10GB 日志怎么统计？→ 分块读取 + 字典聚合；每个进程处理一个分片（`multiprocessing`），结果按 key 合并（对应 Q137 的分块统计题）。

### 2.9 线程安全单例与线程池（Q43、Q50）

**为什么单例要加锁**：`if cls._instance is None` 的检查与赋值不是原子的，两个线程可能同时通过检查，各创建一份。**双重检查锁（double-checked locking）**：先不加锁快速判断，再在锁内二次判断。

```python
import threading

class Singleton:
    _instance = None
    _lock = threading.Lock()

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:            # 第一次快速判断，避免每次抢锁
            with cls._lock:
                if cls._instance is None:    # 锁内二次判断，保证只有一个
                    cls._instance = super().__new__(cls)
        return cls._instance
```

**线程池**：现代写法直接用 `concurrent.futures.ThreadPoolExecutor`，不要手写管理线程：

```python
from concurrent.futures import ThreadPoolExecutor

def run_tasks(items, worker, workers=4):
    with ThreadPoolExecutor(max_workers=workers) as pool:
        return list(pool.map(worker, items))
```

**面试怎么答（Q50）**：线程池解决"频繁创建/销毁线程"的开销和"无上限并发"的风险；核心参数是 `max_workers`（IO 密集可以大、CPU 密集 ≈ 核数）；`ThreadPoolExecutor` 内部就是"任务队列 + 固定 worker 消费"。

**追问**：CPU 密集任务用线程池对吗？→ 不对，GIL 会让多线程退化为单核；CPU 密集用 `ProcessPoolExecutor` 或多进程，注意序列化开销。

### 2.10 Python 原理速查（被追问的隐藏知识点）

- **内存模型**：一切皆对象，变量是引用；`sys.getrefcount` 可以看引用计数；循环引用由垃圾回收（分代 GC）处理。
- **执行模型**：源码 → 字节码（`.pyc`）→ 虚拟机解释执行；`dis` 模块可以看字节码。
- **字符串**：`str` 是 Unicode 序列，编码/解码要显式指定（`encode("utf-8")`）；中文默认 UTF-8。
- **`in` 的复杂度**：对 `list` 是 O(n)，对 `set`/`dict` 是 O(1)——LeetCode 里"查重"用 set。
- **`sorted` 稳定性**：Python 排序稳定，可用多级排序：`sorted(xs, key=lambda x: (-cnt[x], x))`（先按次数降序再按值升序）。
- **切片**：`s[::-1]` 反转；`s[::2]` 取偶数位；切片越界不报错，静默截断。
- **`zip`/`enumerate`**：`for i, (a, b) in enumerate(zip(x, y))` 是高频写法。
- **集合运算**：`A & B` 交集、`A | B` 并集、`A - B` 差集，直接用于"共同好友/差异统计"。

### 3.0 复杂度方法论：如何回答"时间/空间复杂度"

#### 3.0.1 大 O 到底是什么

大 O 描述的是**当输入规模 n 趋向无穷大时，运行时间/内存随 n 增长的数量级上界**。三个要点：

1. **只看增长趋势，忽略常数**：`3n + 100` 和 `1000n` 都是 O(n)。面试时说"常数不重要，关心量级"。
2. **只看最高阶项**：`n² + n + 100` 是 O(n²)。低阶项在 n 大时无足轻重。
3. **是最坏情况上界**：默认讨论最坏情况（除非题目明确问平均/最好，如快排）。

#### 3.0.2 回答复杂度的四步流程（面试直接背这套话术）

> "第一步，确定输入规模是 n（数组长度/字符串长度/树节点数/网格边长）。第二步，找算法的主循环或递归，数最内层操作的执行次数。第三步，把循环嵌套和递归展开成表达式。第四步，化简到最高阶项。"

举例：

```python
def example(nums, target):
    n = len(nums)
    seen = set()                  # O(1) 空间
    for i, x in enumerate(nums):  # 循环 n 次
        if target - x in seen:    # set 查找 O(1)
            return True
        seen.add(x)               # O(1)
    return False
# 时间复杂度：O(n)（一次遍历，每次 O(1)）
# 空间复杂度：O(n)（set 最多存 n 个元素）
```

#### 3.0.3 常见复杂度速查表（要能秒答）

| 复杂度 | 典型算法 | n=100000 时的量级感受 |
| --- | --- | --- |
| O(1) | 哈希表查找、数组按下标访问 | 常数 |
| O(log n) | 二分、平衡树查找 | 约 17 步 |
| O(n) | 一次遍历、双指针 | 10 万步，轻松 |
| O(n log n) | 排序、归并、堆 | 约 170 万步，轻松 |
| O(n²) | 双重循环、朴素 DP | 100 亿步，不可行 |
| O(2^n) | 子集枚举 | n=20 已接近极限 |
| O(n!) | 全排列枚举 | n=10 已接近极限 |

**经验法则**：n ≤ 10 的 6 次方可 O(n)；n ≤ 10 的 5 次方可 O(n log n)；n ≤ 1000 可 O(n²)；n ≤ 20 可 O(2^n)；n ≤ 10 可 O(n!)。这是"1 秒左右"的粗略估计，面试用它判断"这个暴力行不行"。

#### 3.0.4 递归复杂度怎么算（递归树与主定理）

递归复杂度 = 递归调用次数 × 每次调用的开销。两种方法：

**递归树法**（通用）：画一棵调用树，把每层的总工作量加起来。归并排序 `T(n) = 2T(n/2) + O(n)`：每层总工作量 O(n)，层数 log n，共 O(n log n)。

**主定理**（快速）：`T(n) = aT(n/b) + O(n^d)`，比较 `n^d` 与 `n^(log_b a)`：

- 若 `n^d` 更大 → O(n^d)；
- 若两者相等 → O(n^d log n)；
- 若 `n^(log_b a)` 更大 → O(n^(log_b a))。

**面试常见追问**：

- 快排复杂度？→ 平均 O(n log n)，最坏 O(n²)（每次选到极端 pivot，如已排序数组固定选首元素），随机/三数取中可让最坏概率趋近 0。
- 二分查找复杂度？→ O(log n)，因为每轮把搜索区间砍半。
- 递归 DFS 二叉树的时间复杂度？→ O(n)（每个节点访问一次），空间 O(h)（递归栈深度 = 树高，最坏斜树 O(n)）。

#### 3.0.5 空间复杂度怎么答

空间 = **额外分配的数据结构 + 递归栈深度**，不包括输入本身。回答模板：

> "额外用了一个哈希表，最多 O(n)；递归深度是树高 h，最坏 O(n)，平均 O(log n)。总空间 O(n)。"

**易错点**：

- 快排"非原地"版本（用列表推导式）空间 O(n)；"原地"版本空间 O(log n)（递归栈）。
- BFS 用队列，最坏队列里存一整层节点，空间 O(树宽) ≈ O(n)。
- 说"原地"必须确认没有额外数组。

#### 3.0.6 均摊复杂度（amortized）

均摊不是平均：它说的是**连续多次操作的总成本分摊到每次**。典型例子：Python `list.append` 偶尔扩容拷贝 O(n)，但扩容次数少，均摊 O(1)；哈希表插入同理。面试被问"为什么 append 是 O(1)"就这么答。

#### 3.1.3 Python 高频技巧清单（每题都能用上）

- 两数交换：`a, b = b, a`；数组内交换 `nums[i], nums[j] = nums[j], nums[i]`。
- 遍历同时要下标：`for i, x in enumerate(nums)`。
- 找最大/最小 k 个：`heapq.nlargest(k, ...)` / `heapq.nsmallest`。
- 判空：`if not arr:`（空列表/空串/None 都是 falsy）。
- 字符串反转：`s[::-1]`；数组反转：`nums.reverse()`。
- 排序后按多键：`sorted(xs, key=lambda x: (x[0], -x[1]))`。
- 网格四方向：`for di, dj in ((1,0),(-1,0),(0,1),(0,-1))`。
- 初始化二维数组：`dp = [[0] * m for _ in range(n)]`——**不要**用 `[[0]*m]*n`（共享行！）。
- 取中间：`mid = (lo + hi) // 2`（Python 无溢出问题，直接这么写）。
- 字符判断：`c.isdigit()`、`c.isalpha()`、`c.isalnum()`、`c.lower()`。
- 字典计数简写：`cnt[x] = cnt.get(x, 0) + 1`。
- 贪心/区间按起点排序：`intervals.sort(key=lambda x: x[0])`。


### 3.2 二分查找：一套模板吃透所有变体（Q37、Q40、Q33、Q34、Q69、Q153）

**用二分的前提**：数组满足单调性（有序），或题目可以转化为"对答案做可行性判断且判断结果单调"（答案二分）。二分 = 每轮把搜索空间砍半，所以 O(log n)。

#### 3.2.1 标准查找（左闭右闭，Q37/704）

```python
def search(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

#### 3.2.2 lower_bound：第一个大于等于 target（Q40）

```python
def lower_bound(nums, target):
    lo, hi = 0, len(nums)          # 注意：hi 开区间，可能返回 len(nums)
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] < target:
            lo = mid + 1           # mid 太小，排除
        else:
            hi = mid               # mid 满足条件，保留 mid 继续左缩
    return lo                      # 第一个 >= target 的下标
```

**为什么 lo 更新为 mid+1 而 hi 更新为 mid**：我们要找"第一个满足条件的位置"，所以满足条件时不能把 mid 丢掉，只能把右边界缩到 mid；不满足时 mid 一定不是答案，可以排除。记住：**lower_bound 是"排除不满足的左半，保留满足的右边界"**。

#### 3.2.3 由 lower_bound 派生的所有变体（面试秒答）

- 第一个大于等于 target：`lower_bound(nums, target)`。
- 第一个大于 target：`lower_bound(nums, target + 1)`。
- 最后一个小于 target：`lower_bound(nums, target) - 1`。
- 等于 target 的个数：`lower_bound(nums, target + 1) - lower_bound(nums, target)`。

#### 3.2.4 答案二分（"最大值最小化"类）

当"直接对数组二分"不行时，对**答案**二分：写一个 `check(mid)` 判断"答案不超过 mid 是否可行"，check 单调即可。

```python
def min_xxx(nums, k):
    def check(mid):     # 假设答案为 mid，判断是否可行（单调函数）
        cnt = 1
        cur = 0
        for x in nums:
            if cur + x > mid:
                cnt += 1
                cur = x
            else:
                cur += x
        return cnt <= k

    lo, hi = max(nums), sum(nums)   # 答案下界与上界
    while lo < hi:
        mid = (lo + hi) // 2
        if check(mid):
            hi = mid               # 可行就尝试更小
        else:
            lo = mid + 1           # 不可行就加大
    return lo
```

**易错点**：

- 死循环：`lo < hi` 且 `lo = mid + 1` 的组合不会死循环；但若出现 `lo = mid`（求上界时）必须用 `mid = (lo + hi + 1) // 2` 向上取整。
- Python 里 `mid = (lo + hi) // 2` 不会溢出；C++/Java 才需要 `lo + (hi - lo) // 2`。
- 旋转排序数组（Q33）：先判断 `nums[lo] <= nums[mid]` 确定左半有序，再判断 target 是否落在有序半区内，缩小范围。

### 3.3 双指针与滑动窗口（Q23、Q11、Q15、Q49、Q3、Q76、Q438）

#### 3.3.1 双指针两类：相向与同向

- **相向双指针**：左右各一个指针往中间走，用于"有序数组找两数"（Q23 排序版、三数之和 Q15）、"盛水"（Q11）、"判断回文"（Q45）、"移动零"（Q49，一个指针管写入、一个管扫描）。
- **快慢指针**：一个快一个慢，用于链表判环（Q141）、找中点、原地去重。

**为什么相向双指针正确（以两数之和为例）**：数组有序。`s = nums[l] + nums[r]`，若 `s < target`，说明 `nums[l]` 与任何右边的数相加都不可能更大，`l` 可以安全右移——这就是"排除不可能的候选"，因此不会漏解。复杂度 O(n)。

#### 3.3.2 滑动窗口模板（子串/子数组类问题的万能框架，Q3、Q76、Q438）

**适用场景**：连续子数组/子串，需要"最长/最短/恰好包含某些字符"。**为什么 O(n)**：right 只向右移 n 次，left 也只向右移 n 次，每个元素最多进出窗口各一次。

```python
def min_window(s, t):
    from collections import Counter
    need, window = Counter(t), Counter()
    have, need_cnt = 0, len(need)          # 已满足的字符种类数
    left, ans_l, ans_len = 0, 0, float("inf")
    for right, c in enumerate(s):          # 1. 右指针扩张
        window[c] += 1
        if c in need and window[c] == need[c]:
            have += 1
        while have == need_cnt:            # 2. 窗口满足条件后，左指针收缩
            if right - left + 1 < ans_len:
                ans_len, ans_l = right - left + 1, left
            d = s[left]
            window[d] -= 1
            if d in need and window[d] < need[d]:
                have -= 1
            left += 1
    return "" if ans_len == float("inf") else s[ans_l:ans_l + ans_len]
```

**五步记忆法**：扩张右指针 → 更新窗口状态 → 满足条件时收缩左指针 → 收缩前/时更新答案 → 移出左边界并回滚状态。

**变体**：

- 无重复字符最长子串（Q3）：窗口内用 dict 记录字符下标，遇重复直接跳 left。
- 找异位词（Q438/Q567）：窗口长度固定，比较 Counter 是否相等。
- 窗口内求和/计数：维护 `cur`，右加左减。

### 3.4 哈希表与前缀和（Q23、Q48、Q128、Q560、Q437）

**核心思想：把"查找"从 O(n) 降到 O(1)，用空间换时间。** 几乎任何"查重/查找是否出现过"的题，第一反应就是哈希。

#### 3.4.1 两数之和（Q23）

```python
def two_sum(nums, target):
    seen = {}
    for i, x in enumerate(nums):
        if target - x in seen:          # 查"补数"是否出现过
            return [seen[target - x], i]
        seen[x] = i
    return []
# 时间 O(n)，空间 O(n)
```

**为什么"边遍历边存"正确**：对每个 x，只查它之前的数；若答案存在，当遍历到后一个数时，前一个数一定已在 seen 里。**追问**：返回下标且数组无序 → 必须哈希；若有序 → 双指针 O(1) 空间。

#### 3.4.2 前缀和 + 哈希（Q560 和为 K 的子数组）

**核心公式**：`子数组和 [j, i] = prefix[i] - prefix[j-1]`。要 `prefix[i] - prefix[j-1] == k` 等价于统计"之前出现过多少个 `prefix[i] - k`"。所以用一个哈希表记录每个前缀和出现的次数。

```python
def subarray_sum(nums, k):
    pref = {0: 1}          # 前缀和为 0 出现 1 次（空前缀）
    cur = ans = 0
    for x in nums:
        cur += x
        ans += pref.get(cur - k, 0)   # 有多少个 j 使 prefix[j-1] == cur - k
        pref[cur] = pref.get(cur, 0) + 1
    return ans
# 时间 O(n)，空间 O(n)
```

**为什么初始放 `{0: 1}`**：因为 `prefix[j-1]` 可能是 0（从下标 0 开始的子数组），必须预先登记。这是高频易错点。

**变体**：Q437 路径总和 III（树上前缀和 + 回溯撤销）、Q525 连续子数组、矩阵子矩阵和。

#### 3.4.3 最长连续序列（Q128）

要求 O(n)：不能用排序。思路——把所有数放进 set，然后只对"序列起点"（`x-1` 不在 set 中）向后延伸：

```python
def longest_consecutive(nums):
    s = set(nums)
    best = 0
    for x in s:
        if x - 1 not in s:            # 只从起点开始，保证 O(n)
            y = x + 1
            while y in s:
                y += 1
            best = max(best, y - x)
    return best
```

**为什么整体是 O(n)**：内层 while 只在"起点"触发，且每个元素最多被延伸一次，总延伸次数 O(n)。

#### 3.4.4 异位词（Q48）

```python
from collections import Counter

def is_anagram(s, t):
    return Counter(s) == Counter(t)   # 也可用数组计数：cnt = [0]*26
```

**追问**：只含小写字母时用 `[0] * 26` 数组代替 dict，时间 O(n)、空间 O(1)（固定 26）。进阶：变位词分组（Q49）用"排序后的字符串"或"计数字符串"当 key。



### 3.5 链表：指针操作三板斧（Q25、Q27、Q33、Q23、Q41）

链表题 90% 靠三样东西：**改链前先存后继、哑节点（dummy）、快慢指针**。

- 改链前先存后继：`nxt = cur.next`，否则断链后整段丢失。
- 哑节点：头节点可能被修改（反转、删除、合并）时，用 `dummy` 让"头的前驱"存在，少写大量空指针判断。
- 快慢指针：判环、找中点、找倒数第 k 个节点。

#### 3.5.1 反转链表（Q27/206）

```python
def reverse_list(head):
    prev, cur = None, head
    while cur:
        nxt = cur.next      # 1. 先保存后继，否则断链后找不到
        cur.next = prev     # 2. 当前指针指向前驱（反转）
        prev, cur = cur, nxt  # 3. 双指针整体前移
    return prev             # prev 最终指向新头
```

复杂度：O(n) 时间、O(1) 空间。**面试怎么答**："三指针迭代，核心是每次循环完成『保存后继→反转→前移』三步，循环不变量是 prev 指向已反转部分的新头。"

追问：
- 反转区间 [left, right]（Q92）→ 记录 left 前驱与 right 后继，区间内反转后把两端接回；
- K 个一组反转（Q25）→ 先数长度，不足 k 直接返回；每组反转后把"上一组尾"接到"本组新头"，注意哑节点串联。

#### 3.5.2 环形链表（Q33/141）与入环节点（Q142）

```python
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            return True
    return False
```

**为什么快慢指针一定会相遇（知其所以然）**：慢指针每次 1 步、快指针每次 2 步，两者速度差为 1。进入环后，环内距离每轮缩小 1，最终必然追上；若速度差是 2（快指针 3 步），可能正好"跨过"慢指针，相遇就成了概率事件。这也是面试官常追问的点。

**入环节点（Q142）**：第一次相遇后，把一个指针放回 head，两指针同速（都每次 1 步）走，再次相遇的位置就是环入口。证明：设 head 到入口距离 a、入口到相遇点距离 b、环长 c。快指针路程是慢指针的 2 倍：a + b + mc = 2(a + b) ⇒ a = mc − b，即 a ≡ −b (mod c)。所以从相遇点再走 a 步恰好回到入口。

复杂度：O(n) 时间、O(1) 空间。

#### 3.5.3 相交链表（Q160）

```python
def get_intersection_node(headA, headB):
    a, b = headA, headB
    while a is not b:
        a = a.next if a else headB
        b = b.next if b else headA
    return a
```

**为什么正确**：两个指针都走"链表 A + 链表 B"的总路程。若相交，第一轮结束两指针"错位"，第二轮在交点相遇；若不相交，最终同时走到 None 并返回 None。复杂度 O(n + m) 时间、O(1) 空间。

#### 3.5.4 合并两个有序链表（Q25/21）与 K 个升序链表（Q23）

```python
def merge_two_lists(l1, l2):
    dummy = cur = ListNode(0)
    while l1 and l2:
        if l1.val <= l2.val:
            cur.next = l1
            l1 = l1.next
        else:
            cur.next = l2
            l2 = l2.next
        cur = cur.next
    cur.next = l1 or l2      # 剩余整段直接接上
    return dummy.next
```

K 个升序合并用**小根堆**。Python 坑：`heapq` 比较元组时，若 `val` 相等会继续比较第二个元素，而 ListNode 没有定义 `<`，直接写 `(node.val, node)` 会抛 TypeError——必须带上递增下标 `(node.val, i, node)`。

```python
import heapq

def merge_k_lists(lists):
    heap = []
    for i, node in enumerate(lists):
        if node:
            heapq.heappush(heap, (node.val, i, node))
    dummy = cur = ListNode(0)
    while heap:
        _, i, node = heapq.heappop(heap)
        cur.next = node
        cur = cur.next
        if node.next:
            heapq.heappush(heap, (node.next.val, i, node.next))
    return dummy.next
```

复杂度 O(N log k)：N 为总节点数，堆大小恒为 k。追问：不用堆怎么做 → 分治两两合并（归并式），复杂度相同。

### 3.6 栈与单调栈：最近匹配与"第一个更大/更小"（Q24、Q42、Q739、Q84）

**栈的本质**是维护"最近未决"的上下文：括号匹配、函数调用栈、撤销操作、浏览器后退都是同一模型——后进先出 = 最近优先。

**单调栈的"为什么"**：它让每个元素入栈、出栈恰好一次，元素出栈的那一刻就能确定它的"右侧第一个更大（或更小）元素"是谁。暴力 O(n²) 的浪费在于对每个位置向右重复扫描；单调栈把每次比较的结果"复用"给所有被弹出的元素，总比较次数降为 O(n)。

#### 3.6.1 有效括号（Q24/20）

```python
def is_valid(s):
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []
    for c in s:
        if c in pairs:                    # 右括号：必须匹配"最近"的左括号
            if not stack or stack.pop() != pairs[c]:
                return False
        else:                             # 左括号：入栈等待匹配
            stack.append(c)
    return not stack
```

**为什么不能用计数**：`([)]` 中左右括号数量各半，计数会误判合法；但"最近的未匹配左括号"是 `[`，与 `)` 不配对。栈保存的正是"最近的未决左括号"。

追问：最长有效括号（Q32）→ 栈存下标，遇到右括号且栈顶匹配则弹栈并更新答案；或一维 DP（`dp[i]` = 以 i 结尾的最长有效括号长度）。

#### 3.6.2 每日温度（Q739）

```python
def daily_temperatures(temps):
    n = len(temps)
    ans = [0] * n
    stack = []                # 存下标，栈底到栈顶温度递减
    for i, t in enumerate(temps):
        while stack and temps[stack[-1]] < t:
            j = stack.pop()
            ans[j] = i - j    # 当前 i 就是 j 右边第一个更高温度
        stack.append(i)
    return ans
```

要点：当前温度比栈顶高时，栈顶的"右边第一个更高温度"就是当前下标，弹出并结算。

#### 3.6.3 柱状图最大矩形（Q84）

```python
def largest_rectangle_area(heights):
    heights = [0] + heights + [0]   # 哨兵：保证最后能强制弹空栈
    stack = []
    ans = 0
    for i, h in enumerate(heights):
        while stack and h < heights[stack[-1]]:
            cur_h = heights[stack.pop()]
            ans = max(ans, cur_h * (i - stack[-1] - 1))
        stack.append(i)
    return ans
```

**为什么正确**：对每个柱子，以它为高的最大矩形 = 高度 × (右边第一个更矮下标 − 左边第一个更矮下标 − 1)。弹出时，新栈顶就是"左边第一个更矮"，当前 i 就是"右边第一个更矮"。**易错点**：宽度是 `i - stack[-1] - 1`（用弹出后的新栈顶），不是 `i - 弹出下标`；两侧哨兵 0 保证栈最终清空。

#### 3.6.4 用栈实现队列（Q42）

```python
class MyQueue:
    def __init__(self):
        self.in_stack = []
        self.out_stack = []

    def push(self, x):
        self.in_stack.append(x)

    def _move(self):
        if not self.out_stack:
            while self.in_stack:
                self.out_stack.append(self.in_stack.pop())

    def pop(self):
        self._move()
        return self.out_stack.pop()

    def peek(self):
        self._move()
        return self.out_stack[-1]

    def empty(self):
        return not self.in_stack and not self.out_stack
```

**复杂度怎么答（均摊分析实例）**：push 严格 O(1)；pop/peek 均摊 O(1)——因为每个元素最多被"倒一次"，n 次操作总代价 O(n)。这就是 3.0.6 讲的均摊复杂度。

#### 3.6.5 括号生成（Q22）：回溯 + 剪枝

```python
def generate_parenthesis(n):
    ans = []

    def dfs(left, right, path):
        if len(path) == 2 * n:
            ans.append("".join(path))
            return
        if left < n:                    # 左括号没用完就能加
            path.append('(')
            dfs(left + 1, right, path)
            path.pop()
        if right < left:                # 右括号不能多于左括号（前缀合法性）
            path.append(')')
            dfs(left, right + 1, path)
            path.pop()

    dfs(0, 0, [])
    return ans
```

**为什么剪枝条件是 `right < left`**：任意前缀中右括号数一旦超过左括号数，这个前缀就已经非法，后续无论怎么补都救不回来，直接剪掉。结果数量是卡特兰数 C(2n, n)/(n + 1)。


### 3.7 LRU 缓存与原地哈希（Q41、Q51）

#### 3.7.1 LRU Cache（Q41/146）：数据结构推导过程

LRU = Least Recently Used，缓存满时淘汰"最久没被访问"的键。**不要背代码，先推数据结构**：

- 需要 O(1) 查键 → 哈希表；
- 需要 O(1) 删除最旧、O(1) 把访问过的提到最新 → 双向链表（删除任意节点必须知道它的前驱，单链表做不到）；
- 哈希表的值指向链表节点 → "查 → 定位 → 改序"全链路 O(1)。

```python
class Node:
    def __init__(self, key=0, value=0):
        self.key, self.value = key, value
        self.prev = self.next = None

class LRUCache:
    def __init__(self, capacity):
        self.cap = capacity
        self.map = {}
        self.head, self.tail = Node(), Node()   # 哨兵，避免空指针判断
        self.head.next, self.tail.prev = self.tail, self.head

    def _remove(self, node):
        node.prev.next = node.next
        node.next.prev = node.prev

    def _add_to_head(self, node):
        nxt = self.head.next
        self.head.next = node
        node.prev = self.head
        node.next = nxt
        nxt.prev = node

    def get(self, key):
        if key not in self.map:
            return -1
        node = self.map[key]
        self._remove(node)
        self._add_to_head(node)      # 访问即"最近使用"，必须移动
        return node.value

    def put(self, key, value):
        if key in self.map:
            self._remove(self.map[key])
        node = Node(key, value)
        self.map[key] = node
        self._add_to_head(node)
        if len(self.map) > self.cap: # 超容量，淘汰链表尾部
            last = self.tail.prev
            self._remove(last)
            del self.map[last.key]
```

**为什么 get 也要移动节点**：不更新访问顺序就无法准确判定"最久未使用"。追问：`OrderedDict` 一行版 → `move_to_end` + `popitem(last=False)`，底层正是哈希表 + 双向链表；再追问 LFU（Q460）→ 哈希表 + 频率桶双向链表。

#### 3.7.2 原地哈希：缺失的第一个正数（Q51/41）

题目要求 O(n) 时间、O(1) 额外空间 → 必须复用原数组。"原地哈希"的思路：**把数组本身当哈希表**，下标 i 应放数值 i + 1；通过交换把每个数放到"它应该在的位置"，再扫描找第一个对不上号的。

```python
def first_missing_positive(nums):
    n = len(nums)
    for i in range(n):
        while 1 <= nums[i] <= n and nums[nums[i] - 1] != nums[i]:
            j = nums[i] - 1
            nums[i], nums[j] = nums[j], nums[i]
    for i in range(n):
        if nums[i] != i + 1:
            return i + 1
    return n + 1
```

**易错点（必考）**：必须先存 `j = nums[i] - 1` 再交换。若写成 `nums[i], nums[nums[i] - 1] = nums[nums[i] - 1], nums[i]`，Python 会先计算右边、再从左到右赋值，`nums[i]` 更新后左边第二个下标就指向了错误位置。

**为什么整体 O(n)**：每次交换都至少把一个数送到最终位置，最多交换 n 次；不在 [1, n] 范围的值直接跳过，不影响正确性（它们反正不可能是答案）。

### 3.8 DFS / BFS / 回溯：Python 万能模板（Q30、Q46、Q47、Q200、Q79）

搜索题占笔试 30% 以上。先建立选型直觉，再背模板：

- 求**最短步数 / 最少操作 / 按层扩散** → BFS（队列 + 按层处理）；
- 求**所有方案 / 路径 / 组合排列** → DFS 回溯；
- **树** → 递归天然适配；**图 / 网格** → 必须防重复访问（visited 集合或原地标记）；
- 树求深度用 DFS，求最近公共祖先用递归后序。

#### 3.8.1 二叉树遍历与最大深度（Q30、Q47）

前序 / 中序 / 后序只差 visit 的位置，模板统一：

```python
def max_depth(root):                 # Q47
    if not root:
        return 0
    return 1 + max(max_depth(root.left), max_depth(root.right))
```

复杂度：O(n) 时间；空间 O(h)，h 为树高（最坏退化成链时 h = n，即最坏 O(n)）。

层序 BFS（Q30/102）：

```python
from collections import deque

def level_order(root):
    if not root:
        return []
    q = deque([root])
    ans = []
    while q:
        level = []
        for _ in range(len(q)):      # 关键：先快照当前层大小
            node = q.popleft()
            level.append(node.val)
            if node.left:
                q.append(node.left)
            if node.right:
                q.append(node.right)
        ans.append(level)
    return ans
```

**为什么必须先 `len(q)` 快照**：循环内会继续入队下一层节点，若不快照，for 会遍历到刚入队的节点，把两层混在一起。锯齿层序（Q103）→ 按层号反转。

#### 3.8.2 网格岛屿（Q200）：DFS 洪水填充

```python
def num_islands(grid):
    if not grid:
        return 0
    m, n = len(grid), len(grid[0])
    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]
    def dfs(i, j):
        if not (0 <= i < m and 0 <= j < n) or grid[i][j] != '1':
            return
        grid[i][j] = '0'          # 原地标记，代替 visited
        for di, dj in dirs:
            dfs(i + di, j + dj)
    cnt = 0
    for i in range(m):
        for j in range(n):
            if grid[i][j] == '1':
                cnt += 1
                dfs(i, j)
    return cnt
```

复杂度 O(mn)。**易错点**：先判断越界再访问；标记必须在递归/入队前完成，否则同一块陆地会被反复处理甚至死循环。追问：最大岛屿面积（Q695）→ dfs 返回连通块大小并求和；BFS 版 → 队列存 (i, j) 坐标元组。

#### 3.8.3 回溯万能模板：全排列 / 组合 / 子集（Q46、Q78）

口诀：**for 横向遍历 + 递归纵向深入 + 撤销（path.pop()）**。

- 子集 / 组合：不回头选，用 `start` 参数控制起点；
- 全排列：每个元素恰好用一次，用 `used` 数组；
- 去重：先排序，跳过"同一层重复值"。

```python
def subsets(nums):                 # Q78 子集
    ans = []
    def dfs(start, path):
        ans.append(path[:])        # 必须拷贝！
        for i in range(start, len(nums)):
            path.append(nums[i])
            dfs(i + 1, path)
            path.pop()
    dfs(0, [])
    return ans

def permute(nums):                 # Q46 全排列
    ans = []
    used = [False] * len(nums)
    def dfs(path):
        if len(path) == len(nums):
            ans.append(path[:])
            return
        for i in range(len(nums)):
            if used[i]:
                continue
            used[i] = True
            path.append(nums[i])
            dfs(path)
            path.pop()
            used[i] = False
    dfs([])
    return ans
```

**回溯第一高频 bug**：`ans.append(path)` 而不是 `ans.append(path[:])`。path 是同一个可变对象，后续 pop 会把它清空，最终 ans 里全是同一个空列表。

去重模板（先排序）：
- 组合去重：`if i > start and nums[i] == nums[i - 1]: continue`；
- 全排列去重：`if used[i] or (i > 0 and nums[i] == nums[i - 1] and not used[i - 1]): continue`。

**为什么是 `not used[i - 1]`**：去重要去掉的是"同一层"的重复分支。排序后相同值相邻：若前一个相同值还没被用过，说明当前是"同一层跳过它再选我"的重复分支，剪掉；若前一个在路径里（used 为 True），说明是"同一分支"的连续重复，必须保留。

复杂度：全排列 O(n · n!)，子集 O(n · 2^n)；空间 = 递归深度 × path 长度。

#### 3.8.4 单词搜索（Q79）：网格回溯 + 恢复现场

```python
def exist(board, word):
    m, n = len(board), len(board[0])
    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]
    def dfs(i, j, k):
        if k == len(word):
            return True
        if not (0 <= i < m and 0 <= j < n) or board[i][j] != word[k]:
            return False
        tmp = board[i][j]
        board[i][j] = '#'          # 占用：防止走回头路
        for di, dj in dirs:
            if dfs(i + di, j + dj, k + 1):
                return True
        board[i][j] = tmp          # 恢复现场（回溯）
        return False
    for i in range(m):
        for j in range(n):
            if dfs(i, j, 0):
                return True
    return False
```

复杂度 O(mn · 4^L)，L 为单词长度：每个起点最多 4 个分支、深度 L，乘上 mn 个起点。追问：单词搜索 II（Q212）→ 用前缀树（Trie）让多个单词共享前缀，避免重复搜索。


### 3.9 动态规划：从"暴力"到"最优"的思考链（Q34、Q36、Q51、Q121、Q300、Q322、Q42、Q152）

先背四步框架，再谈"为什么"：

1. **定义状态** dp[i]：说清"下标含义 + 值含义"；
2. **写转移方程**：从"最后一步"倒推，dp[i] 由哪些更小的子问题组合而成；
3. **初始化 + 遍历顺序**：一维从左到右；二维看依赖方向决定先行还是先列；
4. **空间优化**：只依赖前 k 个状态就用滚动数组。

**为什么 DP 快**：重叠子问题 + 最优子结构。暴力递归会把同一子问题重复计算指数次，DP 用表缓存，每个子问题只算一次。**面试答复杂度公式**：DP 时间 = 状态数 × 每个状态的转移成本；空间 = 状态表大小（可优化）。

#### 3.9.1 爬楼梯（Q36/70）

```python
def climb_stairs(n):
    a, b = 1, 1
    for _ in range(2, n + 1):
        a, b = b, a + b
    return b
```

dp[i] = dp[i-1] + dp[i-2]：最后一步要么迈 1 阶、要么迈 2 阶，两种情况互斥且完备。为什么空间 O(1)：只依赖前两个状态。追问：打家劫舍（Q198）→ dp[i] = max(dp[i-1], dp[i-2] + nums[i])，本质是"偷不偷 i"的决策。

#### 3.9.2 最大子数组和（Q34/53）：Kadane

```python
def max_sub_array(nums):
    cur = ans = nums[0]
    for x in nums[1:]:
        cur = max(x, cur + x)     # 以 x 结尾的最大和
        ans = max(ans, cur)
    return ans
```

状态是"以 i 结尾的最大子数组和"：要么自己单开（前面累加是负的、拖后腿），要么续上前缀。**为什么对**：全局最大子数组一定以某个位置结尾，所以扫一遍取 max 即可。追问：环形数组（Q918）→ max(普通 Kadane, 总和 − 最小子数组和)；要返回区间 → 记录 start 下标。

#### 3.9.3 买卖股票（Q26/121）

```python
def max_profit(prices):
    low = float('inf')
    ans = 0
    for p in prices:
        low = min(low, p)            # 历史最低价
        ans = max(ans, p - low)      # 今天卖出的最大收益
    return ans
```

**为什么只维护历史最低价就够**：第 i 天卖出的最优选择一定是"前面最低价那天买入"，一个变量就完成了最优子结构。追问：无限次（Q122，累加所有正差价）；带手续费/冷冻期（Q714/Q309，二维状态机 dp[i][0/1] 表示持有/不持有）；最多两次（Q123，四个状态）。

#### 3.9.4 零钱兑换（Q322）：完全背包最值

```python
def coin_change(coins, amount):
    INF = amount + 1
    dp = [INF] * (amount + 1)
    dp[0] = 0
    for i in range(1, amount + 1):
        for c in coins:
            if c <= i:
                dp[i] = min(dp[i], dp[i - c] + 1)
    return dp[amount] if dp[amount] != INF else -1
```

dp[i] = min(dp[i-c] + 1)：凑 i 的最优方案一定以"最后用某枚硬币 c"结尾。**为什么这里正序循环硬币即可（0/1 背包要倒序）**：完全背包中每枚硬币可无限使用，正序允许同一硬币被反复叠加；0/1 背包倒序是为了防止同一物品被重复使用。**易错点**：INF 要够大；无解返回 -1。追问：组合总数（Q518）→ 外层遍历硬币、内层遍历金额得到"组合数"（不区分顺序）；内外层对调则得到"排列数"。

#### 3.9.5 最长递增子序列（Q300）：O(n²) 与 O(n log n)

```python
def length_of_lis(nums):
    dp = [1] * len(nums)
    for i in range(len(nums)):
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp) if dp else 0
```

dp[i] = 以 nums[i] 结尾的 LIS 长度，转移看所有更小值。**O(n log n) 版（讲清原理）**：维护 tails，tails[k] = 长度为 k+1 的 LIS 的最小末尾；对每个 x 用 bisect_left 找第一个 ≥ x 的位置替换。**为什么贪心成立**：末尾越小，未来越容易接长，用最小末尾代表每种长度是"最优可扩展状态"。

#### 3.9.6 接雨水（Q42）：三种解法都要能讲

按列（预处理左右最大值）最直观：

```python
def trap(height):
    n = len(height)
    if n < 3:
        return 0
    left_max = [0] * n
    right_max = [0] * n
    left_max[0] = height[0]
    for i in range(1, n):
        left_max[i] = max(left_max[i - 1], height[i])
    right_max[n - 1] = height[n - 1]
    for i in range(n - 2, -1, -1):
        right_max[i] = max(right_max[i + 1], height[i])
    ans = 0
    for i in range(n):
        ans += max(0, min(left_max[i], right_max[i]) - height[i])
    return ans
```

**为什么每格水量 = min(左侧最高, 右侧最高) − 当前高度**：木桶效应——水只能到两侧较矮那堵墙的高度。**易错点**：`max(0, ...)` 防止高度差为负；n < 3 无法蓄水。

追问：双指针 O(1) 空间（左右指针维护 left_max / right_max，谁矮处理谁）；单调栈（维护递减栈，弹出时计算"横向"蓄水量）。三种解法时间都是 O(n)，面试先讲按列版再降空间。

#### 3.9.7 乘积最大子数组（Q152）：为什么必须维护最小

```python
def max_product(nums):
    cur_max = cur_min = ans = nums[0]
    for x in nums[1:]:
        if x < 0:
            cur_max, cur_min = cur_min, cur_max
        cur_max = max(x, cur_max * x)
        cur_min = min(x, cur_min * x)
        ans = max(ans, cur_max)
    return ans
```

**为什么必须同时维护最小乘积**：负数会让"最大"变"最小"、让"最小"变"最大"（负负得正）。只维护最大值会漏掉"乘一个负数后反转"的情况——这就是子问题之间"状态耦合"的经典例子。


### 3.10 TopK、快排与归并（Q29、Q38、Q39、Q347）

#### 3.10.1 数组第 K 大（Q29/215）：小根堆

```python
import heapq

def find_kth_largest(nums, k):
    heap = nums[:k]
    heapq.heapify(heap)                 # 建大小为 k 的小根堆
    for x in nums[k:]:
        if x > heap[0]:                 # 比堆顶大就替换
            heapq.heapreplace(heap, x)
    return heap[0]
```

**为什么小根堆而不是大根堆**：堆里留的是"当前最大的 k 个"，其中最小的（堆顶）恰好是第 k 大。复杂度 O(n log k)。追问：前 K 个高频元素（Q347）→ Counter 计数后按频次做同样的小根堆；数据规模更大可用桶排序 O(n)。

#### 3.10.2 快排（Q38）与归并（Q39）

```python
def quick_sort(nums):
    if len(nums) <= 1:
        return nums
    pivot = nums[len(nums) // 2]
    left = [x for x in nums if x < pivot]
    mid = [x for x in nums if x == pivot]
    right = [x for x in nums if x > pivot]
    return quick_sort(left) + mid + quick_sort(right)
```

复杂度：平均 O(n log n)，最坏 O(n²)——已排序序列 + 固定枢轴时每次只切掉一个元素，递归树退化成 n 层。**为什么工程上仍广泛用**：常数小、缓存友好；用随机枢轴/三数取中把最坏情况"概率化"。这个简洁版空间 O(n)；原地 partition 版空间 O(log n)（递归栈）。

```python
def merge_sort(nums):
    if len(nums) <= 1:
        return nums
    mid = len(nums) // 2
    return merge(merge_sort(nums[:mid]), merge_sort(nums[mid:]))

def merge(a, b):
    i = j = 0
    ans = []
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            ans.append(a[i]); i += 1
        else:
            ans.append(b[j]); j += 1
    ans += a[i:]
    ans += b[j:]
    return ans
```

归并复杂度恒为 O(n log n)，空间 O(n)，**稳定**；适合链表和外部排序（多路归并）。

**稳定性怎么答**：稳定 = 相等元素的相对顺序不变。归并稳定（相等先取左半）；快排、堆排不稳定（交换会跨越相等元素）；插入、冒泡稳定。为什么重要：多关键字排序时需要保住第一关键字的相对序。

#### 3.10.3 TopK 的快速选择（QuickSelect）

partition 后看枢轴最终下标：等于 k 直接返回；大于 k 只在左半找；小于 k 在右半找。**为什么期望 O(n)**：每次只处理一侧，规模 n + n/2 + n/4 + … = 2n；最坏 O(n²)（每次划分都极不均衡）。

### 3.11 字符串题（Q5、Q31、Q35、Q45）

#### 3.11.1 最长公共前缀（Q31/14）：纵向扫描

```python
def longest_common_prefix(strs):
    if not strs:
        return ""
    for j in range(len(strs[0])):
        c = strs[0][j]
        for s in strs:
            if j >= len(s) or s[j] != c:
                return strs[0][:j]
    return strs[0]
```

复杂度 O(S)，S 为所有字符串总字符数。拿第一个字符串当基准逐字符比对。

#### 3.11.2 回文串判断（Q45）与最长回文子串（Q5）

```python
def is_palindrome(s):                 # Q45：忽略非字母数字、忽略大小写
    l, r = 0, len(s) - 1
    while l < r:
        while l < r and not s[l].isalnum():
            l += 1
        while l < r and not s[r].isalnum():
            r -= 1
        if s[l].lower() != s[r].lower():
            return False
        l += 1
        r -= 1
    return True

def longest_palindrome(s):            # Q5：中心扩展
    n = len(s)
    def expand(l, r):
        while l >= 0 and r < n and s[l] == s[r]:
            l -= 1
            r += 1
        return l + 1, r - 1
    best = ""
    for i in range(n):
        for l, r in (expand(i, i), expand(i, i + 1)):
            if r - l + 1 > len(best):
                best = s[l:r + 1]
    return best
```

**为什么 O(n²)**：共 2n − 1 个中心（奇偶各 n 个），每个中心最多向外扩 n 步。**为什么必须分奇偶**：回文有两种形态（aba 与 abba）。追问：Manacher O(n)——利用已求回文半径的对称性，笔试少考但要知道存在。

#### 3.11.3 字符串相加（Q35/415）：模拟竖式

```python
def add_strings(num1, num2):
    i, j = len(num1) - 1, len(num2) - 1
    carry = 0
    ans = []
    while i >= 0 or j >= 0 or carry:   # 最后可能多一位进位
        a = int(num1[i]) if i >= 0 else 0
        b = int(num2[j]) if j >= 0 else 0
        s = a + b + carry
        ans.append(str(s % 10))
        carry = s // 10
        i -= 1
        j -= 1
    return "".join(reversed(ans))
```

**易错点**：while 条件必须包含 `or carry`（最高位可能产生新进位）；拼接用列表 + join（反复 `s = s + c` 是 O(n²)）。追问：二进制相加（Q67）同样模板，模 2 除 2。

## 四、机器学习基础与指标（对标 Q61–Q70）

### 4.1 偏差-方差分解（Q61）：过拟合/欠拟合是同一个框架

**是什么**：模型预测误差可分解为 Err = Bias² + Variance + 噪声。

- **偏差**：模型预测的期望与真实值的差距——模型"太笨"，表达不了真实规律 → 欠拟合。
- **方差**：模型对训练集扰动的敏感度——换一批训练数据，预测就大变 → 过拟合。
- **噪声**：数据本身不可约的随机性，任何模型都无法消除。

**为什么存在 trade-off**：模型容量越大，越能拟合训练集细节（偏差↓），但越容易被噪声带偏（方差↑）；容量越小则相反。测试误差 = 偏差² + 方差 + 噪声，最优点在两者和最小处，这就是"正则化、早停、集成"的数学根源。

**怎么判断**：训练误差高 + 验证误差高 → 欠拟合（加容量/特征/训练轮数）；训练误差低 + 验证误差高 → 过拟合（加数据/正则/早停/dropout/降容量）。

🎯 **迁移（简历 300 条小样本）**：小样本微调最容易翻车在"验证集过拟合"。被追问就答：小样本先用 K 折交叉验证选点，用 AUC 而非 accuracy，配合数据增强与规则兜底，不把单次准确率当结论。

### 4.2 L1 与 L2 正则（Q62）：为什么 L1 稀疏

**是什么**：L1 = λ‖w‖₁（绝对值之和），L2 = λ‖w‖₂²（平方和）。

**为什么 L1 稀疏（三个层次，挑一个展开就够）**：

1. **梯度层面**：L1 梯度恒为 ±λ，在 0 点不可导，权重被"线性拉向"0，一旦到 0 就停在角点上；L2 梯度为 2λw，越接近 0 梯度越小，只能"压小"不能"归零"。
2. **几何层面**：L1 的约束域是菱形（顶点在坐标轴上），等高线最优点常落在顶点 → 某些维正好为 0；L2 约束域是球面，最优点一般不在坐标轴上。
3. **贝叶斯层面**：L1 等价于 Laplace 先验（尖峰厚尾），L2 等价于 Gaussian 先验。

**为什么 L2 更常用**：L1 对噪声敏感，小数据集可能把重要特征也清零；L2 平滑稳定、数值更稳。🎯 迁移：机审特征工程里 L1 做特征选择，L2 防共线性爆炸。

### 4.3 分类损失函数（Q63）：为什么交叉熵是标配

- **二分类 BCE**：L = −y log p − (1−y) log(1−p)。**为什么用 log**：log 让"错得离谱"的样本梯度巨大（p 接近 0 或 1 时梯度趋于无穷），而"正确且自信"的样本梯度趋近 0，训练效率高。
- **多分类 CE**：L = −log p_true。
- **为什么不直接用 MSE**：MSE 对概率输出求导带 p(1−p) 因子，在错误区域梯度反而小（饱和），收敛慢；交叉熵与 softmax 组合时梯度恰好等于 p − y（干净、无饱和）。
- **类别不平衡**：加权 CE、Focal Loss（见 4.4）。
- **排序/召回场景**：AUC 是排序性质的指标，可直接用 pairwise / ListNet 类损失近似优化。

### 4.4 类别极度不平衡（Q64）：为什么 accuracy 会骗人

**为什么 accuracy 骗人**：99:1 时全预测"正常"也有 99% accuracy，但对违规类的召回是 0——指标与业务目标完全脱节。机审里违规率通常 <1%，这是必考题。

**应对手段（按优先级）**：

1. **换指标**：P/R/F1/AUC/PR-AUC，分桶评估（按置信度区间分桶看准召）；
2. **阈值调整**：模型输出概率后把决策阈值往"违规"方向移动，等价于提高召回（不重训即可换工作点）；
3. **重采样**：欠采样多数类（注意信息损失）、过采样少数类（注意过拟合）、SMOTE 插值；
4. **损失层面**：类别权重、Focal Loss；
5. **数据层面**：难例挖掘、半监督扩充、把问题建模为异常检测。

**Focal Loss 公式**：FL = −α_t (1 − p_t)^γ log(p_t)。**为什么有效**：难分样本 p_t 小，(1−p_t)^γ 接近 1，梯度被保留；易分样本 p_t 大，权重指数衰减，防止海量易分类淹没难例。

### 4.5 Precision / Recall / F1 / AUC / PR-AUC（Q65）：全部手算一遍

先写混淆矩阵：TP = 判违规且真违规；FP = 判违规但正常（**误杀**）；FN = 判正常但真违规（**漏杀**）；TN = 判正常且正常。

- **Precision = TP/(TP+FP)**：抓回来的有多准 → 误杀敏感；
- **Recall = TP/(TP+FN)**：真违规抓出多少 → 漏杀敏感；
- **F1 = 2PR/(P+R)**：P/R 调和平均。**为什么调和平均而不是算术平均**：P=1、R=0 时算术平均 0.5 但 F1=0——调和平均惩罚"偏科"，与"既要准又要全"的业务目标一致；
- **Accuracy = (TP+TN)/总数**：只在类别均衡时可用；
- **误杀率 = FP/(FP+TN)**：正常内容被拒比例（体验指标）；
- **漏杀率 = FN/(FN+TP)**：违规漏过比例（风险指标）；
- **AUC**：ROC 曲线下面积 = 随机正样本排在随机负样本前面的概率；阈值无关，衡量排序能力；
- **PR-AUC**：PR 曲线下面积，正类极稀疏时比 ROC 更敏感（见 4.10）。

**手算示例**：1000 条，实际违规 50 条；模型判违规 60 条，其中 40 条真违规 → TP=40, FP=20, FN=10, TN=930 → P=40/60≈0.667, R=40/50=0.8, F1≈0.727。

**什么时候用哪个**：均衡 → F1；误杀敏感 → Precision；漏杀敏感 → Recall；排序能力 → AUC；稀疏正类 → PR-AUC。🎯 迁移：翻译校对 4.5% 修改率可以讲成"召回被校出的错误 / 人审复核确认"，但必须补上**误改率（Precision）**，否则会被追问。

### 4.6 交叉验证与数据泄漏（Q66、Q113 的前置）

**K 折交叉验证**：把训练集均分 K 份，轮流 1 份做验证、其余训练，指标取平均。**为什么用**：小数据下更稳，减少"单次划分运气"；类别不平衡必用**分层 K 折**（每折类别比例与整体一致）。

**数据泄漏（Leakage）**：训练时"看到了"预测时刻拿不到的信息，导致离线虚高、上线崩盘。典型形态：

- 全量数据做归一化/缺失填充后再切分（正确做法：只在训练折上算统计量）；
- 时间序列用未来数据预测过去（必须按时间切分）；
- 特征含目标泄漏（用标签构造特征、或把"是否违规"当特征）；
- 去重不彻底：同一内容的多版本同时落在训练集和验证集。

**面试怎么答泄漏**：判别标准一句话——"该信息在预测时刻是否可得？"不可得就是泄漏。🎯 迁移：简历里的评估集如果和训练集同源，必须主动说明如何避免文本重复泄漏。

### 4.7 特征工程（Q67）

三类特征：
- **文本**：TF-IDF、词/句向量、BPE token、关键词命中；
- **数值**：分箱、归一化、目标编码；
- **行为/关系**：频次、统计、图特征。

**为什么分箱**：引入非线性、抗异常值、与树模型天然契合。**目标编码（Target Encoding）**：用标签均值编码类别，**注意防泄漏**：必须 out-of-fold 计算。

🎯 迁移（机审特征示例）：文案长度、敏感词命中数、类目、商家历史违规率、图片 OCR 文本、向量相似度、同设备/同资质关联数。

### 4.8 树模型：RF / GBDT / XGBoost（Q68）

- **决策树**：按信息增益 / 基尼系数递归划分。**为什么用基尼**：计算快、对多分类友好。
- **RF（Bagging + 随机特征子集）**：样本扰动 + 特征扰动 → 树间相关性小，平均后方差下降。**为什么能降方差**：方差随样本扰动被平均抵消，偏差基本不变。
- **GBDT**：加法模型，每棵树拟合上一轮的**负梯度**（回归问题即残差）。**为什么拟合残差**：把损失函数泰勒展开，负梯度方向是损失下降最快的方向，每棵树都在"修错"。
- **XGBoost 为什么强**：二阶泰勒展开（近似更准）、显式正则项、列采样、缺失值自动处理、分位近似并行。
- **机审里的地位**：决策路径可审计（申诉解释友好）、适合高维稀疏、能做特征重要度；常与深度模型级联/集成。

### 4.9 少样本学习（Q69，简历 300 条样本怎么答）

**定义**：每类只有极少标注样本的学习。

**方法**：数据增强/回译；预训练迁移（先通用后领域）；Few-shot prompting（ICL）；检索增强（把语义相似的已标注样本拼进 prompt）；伪标签/半监督；主动学习（选最有信息量的样本给人标）；模型层面（元学习、原型网络）。

**小样本三大坑**：过拟合、评估方差大、类别偏置。**回答策略（关键）**：小样本项目不要只报"准确率"，要报交叉验证均值与方差、坏例分析，并把"数据不够"转化为"数据质量 + 规则兜底 + 持续回流"的工程方案——这正好接上机审的 badcase 闭环。

### 4.10 ROC 与 PR 曲线（Q70）：什么时候看哪条

- **ROC**：x = FPR = FP/(FP+TN)，y = TPR = Recall。正负类比例变化时曲线基本不变。
- **PR**：x = Recall，y = Precision。对正类稀疏极其敏感。

**为什么类别不平衡时看 PR 不看 ROC**：负类占绝大多数时，FPR 的分母巨大，FP 增加对 FPR 的影响很小，ROC 显得"乐观"；PR 直接反映"抓回来的那些里有多少是准的"，与业务的误杀成本直接对应。

**机审答法**：上线决策看 PR-AUC 和"固定误杀率下的召回"；报告里单独报 ROC 容易被 99% 正常样本稀释成虚高。


## 五、深度学习与 Transformer 原理（对标 Q71–Q83）

### 5.1 反向传播（Q71）：为什么梯度能"传"回去

**是什么**：链式法则 + 计算图。损失对每层参数求偏导，从输出层往输入层逐层复用"上游梯度"。

**为什么高效**：对每层独立求导要重复计算大量公共子表达式；反向传播沿计算图把梯度"复用"，总计算量只相当于一次前向传播的量级。

**面试手推**：y = wx + b 到 a = sigmoid(y) 再到 L = (a - target)^2，把 dL/dw 按链式拆成 dL/da 乘 da/dy 乘 dy/dw，并指出每个因子在反向过程中被复用。

**梯度消失/爆炸**：深层网络连乘激活导数，sigmoid 导数最大仅 0.25，深层梯度指数衰减到消失。缓解：ReLU、残差连接、合理的初始化（Xavier/He）、BN/LN。**为什么 ReLU 能缓解**：正半轴导数恒为 1，连乘不衰减。

### 5.2 激活函数（Q72）：ReLU 为什么是默认

- **sigmoid**：饱和区梯度约等于 0，深层消失；输出非零中心（恒正），收敛慢（梯度全同号、锯齿路径）。
- **tanh**：零中心、收敛更好，但同样存在饱和。
- **ReLU**：x > 0 时梯度恒 1，不消失、计算快；但负半轴梯度 0，神经元可能"死"（Dead ReLU）。缓解：Leaky ReLU / PReLU。
- **Softmax**：多分类输出归一化成概率分布，配合交叉熵。
- **为什么 Transformer 用 GELU/SiLU**：平滑、处处可导、实验更稳，是 ReLU 的"软"版本。

### 5.3 BN 与 LN（Q73）：归一化到底解决什么

**动机**：每层输入分布随训练漂移（内部协变量偏移），大学习率下不稳定；归一化把激活拉回梯度敏感区。

- **BN（BatchNorm）**：对 batch 维度做归一化，按当前 batch 的每个通道统计均值与方差。问题：依赖 batch size；训练用 batch 统计、推理用滑动均值，训练/推理行为不一致；序列长度变化时不稳定。
- **LN（LayerNorm）**：对每个样本的 hidden 维度归一化。**为什么 Transformer 用 LN**：序列可变长、batch 可以很小、训练与推理完全一致（不依赖 batch 统计）。
- **为什么有效**：归一化后激活分布稳定，允许更大学习率，附带轻微正则。

### 5.4 Dropout（Q74）

**是什么**：训练时以概率 p 随机失活神经元。**为什么有效**：等价于对指数多个子网络做隐式集成；迫使神经元不依赖特定同伴（特征解耦），防止共适应。

**训练/推理差异**：训练随机失活；推理全部保留。现代框架用 inverted dropout：训练时除以 (1-p) 保持输出期望一致，推理时无需任何缩放。

**追问**：Transformer 里 dropout 的常见位置——attention 权重、残差之后、FFN 内部。

### 5.5 优化器（Q75）：SGD 到 Momentum 到 Adam 到 AdamW 的演进

- **SGD**：theta = theta - eta * g。简单，但病态曲率下震荡、收敛慢。
- **Momentum**：v = beta * v + g，用 v 更新。**为什么**：历史梯度叠加，平原区加速、峡谷区平滑震荡。
- **Adam**：一阶矩 m（动量）+ 二阶矩 v（梯度平方 EMA），每参数自适应学习率，带偏差校正。**为什么快**：稀疏梯度也能拿到大步长，不同参数给不同步长。
- **AdamW**：把 weight decay 从 L2 正则中解耦（不参与梯度、不参与二阶矩）。**为什么重要**：L2 与 Adam 的自适应步长耦合会搞乱衰减比例；AdamW 在大模型预训练上显著更稳。
- **大模型标配**：AdamW + warmup + 余弦退火。

### 5.6 warmup（Q76）

**为什么需要**：训练初期 Adam 的二阶矩估计不准（初始 v 小，步长被放大），且模型初始参数是随机的，直接大学习率容易崩。

**怎么做**：线性/常数 warmup 到峰值学习率，再余弦/线性衰减。**什么时候要更长 warmup**：深层 Transformer、大 batch（大 batch 梯度噪声小，可更大步长，但初期更需要稳）。


### 5.7 Self-Attention（Q77、Q79）：公式、直觉与复杂度

**公式**：

```
Q = X W_Q, K = X W_K, V = X W_V
Attention(Q, K, V) = softmax(Q K^T / sqrt(d_k)) V
```

**为什么除以 sqrt(d_k)**：d 维向量点积的方差随维度线性增长（约 d），点积过大后 softmax 进入饱和区、梯度消失；除以 sqrt(d_k) 把方差拉回 O(1)。

**为什么多头**：不同头学到不同的子空间关系（位置、句法、语义），相当于多路并行注意力再拼接。

**复杂度**：时间 O(n^2 * d)（QK^T 矩阵乘法），空间 O(n^2)（注意力矩阵）。n 是序列长度——这是长文本的瓶颈，也是 KV Cache、稀疏注意力、FlashAttention 的动机。**因果掩码**：Decoder 把未来位置的注意力分数置为负无穷，保证只能看到过去。

### 5.8 位置编码（Q78）：RoPE 为什么成为主流

**为什么需要**：自注意力是**排列不变**的——交换 token 顺序，注意力结果相同，必须注入位置信息。

- **绝对位置**：Sinusoidal（三角函数周期编码，可外推到未见长度）、可学习位置 embedding。
- **相对位置**：相对位置偏置（如 T5、Transformer-XL）。
- **RoPE（旋转位置编码）**：把 q、k 向量按位置做旋转，q 与 k 的内积自然携带**相对位置**信息。**为什么强**：同时具备相对位置语义与良好的长度外推性，且与线性注意力兼容。后续 NTK-aware 缩放、YaRN 都是对 RoPE 频率做缩放来外推更长序列。

🎯 简历长文本项目必被追问"RoPE 外推/插值"，答案联动 Q95。

### 5.9 KV Cache（Q79）：推理加速的核心

**是什么**：自回归生成第 t+1 个 token 时，前 t 个 token 的 K、V 不需要重算，缓存下来复用。

**为什么省计算**：免去对历史 token 的重复 QK^T 计算，单步生成的注意力计算从 O(n^2) 降到 O(n)（仍需扫描全部历史）。**代价**：显存随序列长度增长 O(n * d * 层数)。

**衍生优化**：PagedAttention（vLLM，分页管理 KV Cache 减少碎片）、GQA/MQA（多头共享 KV 减少显存）、KV 量化。

**追问**：prefill（预填充）阶段并行计算全部历史 token 的 KV 并缓存；decode（解码）阶段逐 token 生成、只算新 token。

### 5.10 BERT vs GPT（Q80）

- **BERT**：Encoder-only，双向注意力，MLM（掩码语言模型）预训练。**为什么双向好**：理解/分类任务需要看全上下文。
- **GPT**：Decoder-only，因果注意力，自回归预训练。**为什么单向**：生成时必须保证看不到未来。
- **机审分工**：BERT 类做高吞吐初筛（文本分类、NER、文本匹配）；GPT 类做复杂语义判断、证据抽取、多步 Agent。
- **追问：为什么现在主流 LLM 都是 Decoder-only？** 生成任务统一接口（所有任务都能转成生成）、缩放规律稳定、训练/部署简单；Encoder 的"双向优势"在超大模型上不再明显。

### 5.11 微调、Prompt、LoRA 的选型（Q81，细节见 6.9）

- **全参微调**：效果上限最高，但资源大、易灾难遗忘；
- **Prompt/ICL**：不改参数、快速验证，上限依赖模型能力与上下文长度；
- **LoRA/QLoRA**：低秩增量、省显存、可插拔、迭代快，工业界主流；
- **选型逻辑**：看数据量、任务稳定性、部署资源、迭代频率。

### 5.12 ViT 与多模态对齐（Q82）

**ViT**：图片切 patch，线性投影成 patch embedding，加位置编码，进标准 Transformer。**为什么有效**：自注意力天然建模 patch 间长程关系；大规模预训练数据是 ViT 不输 CNN 的关键。

**CLIP**：图文双塔，InfoNCE 对比损失拉近匹配图文对、推开不匹配对。**为什么用对比学习**：无需细粒度标注，从海量弱监督图文对学对齐，得到通用图文表征。

**机审多模态**：CLIP 做图文匹配/检索（如"正常图 + 违规文"的图文不一致检测）；VLM（视觉编码器 + 投影层 + LLM）做开放语义判断与证据定位（输出违规区域/理由）。

### 5.13 GNN 与风控/审核（Q83）

**核心**：消息传递——每层聚合邻居特征更新节点表示。GCN 用归一化邻接矩阵乘以特征，**按度归一化**避免度大的节点特征爆炸。

**为什么风控用图**：黑产是团伙/关系作案（同一设备、同一收款账号、群组关系），单样本独立假设失效，必须用关系建模。

**任务**：节点分类（识别风险账号/内容）、链路预测（发现潜在关联）、社区发现（黑产团伙）。**异构图**（用户/设备/商家/内容多类型节点）需要按边类型分别聚合（RGCN、HAN）。

🎯 迁移：简历里的审核项目若做过"多模型投票"，可升级讲成"以内容为中心的投票网络"——但必须有数据支撑，不能凭空包装。


## 六、NLP 与 LLM 后训练（对标 Q84–Q100）

### 6.1 BPE / WordPiece（Q84）：为什么 LLM 要子词分词

**是什么**：BPE（Byte Pair Encoding）从字符开始，按相邻符号的共现频率反复合并最高频的 pair，形成子词词表。WordPiece 类似，但合并准则用"合并后词表概率提升"。

**为什么用子词而不是整词/单字**：
- 整词表爆炸（词形变化、复合词、多语言），未登录词（OOV）处理不了；
- 单字丢失词义单位、序列变长；
- 子词平衡了词表大小与覆盖率，常见词一个 token、罕见词拆成子词，模型仍能拼回语义。

**中文特殊点**：中文没有天然空格，通常先分词或直接 byte-level BPE；**为什么 Byte-level**：BPE 直接把 UTF-8 字节当符号，天然覆盖所有语言与 emoji，词表固定为 256 起步。

🎯 迁移：简历里做中文剧本/翻译，分词与 BPE 是必被追问的基础，答出"字节级 = 零 OOV + 跨语言统一"就稳。

### 6.2 SFT 数据质量（Q85）：比数量更重要的四件事

1. **指令多样性**：覆盖不同句式、语气、任务类型，防止"只会一种模板"；
2. **答案正确性 + 格式一致性**：截断、缺失推理过程、答案噪声都是数据污染；
3. **难度/领域分布与业务分布一致**：机审 SFT 要按业务类别、风险等级配比；
4. **去重去脏**：模板重复、隐私、仇恨言论、低质数据必须清理。

**质检三层**：规则（长度/格式/去重）→ LLM-as-judge（语义/一致性）→ 人工抽检（小样本精确标注）。**为什么 LLM-as-judge 可行**：判断"哪个更好"比"生成答案"简单，模型间一致性高；但要防 judge 偏好（长度偏好、位置偏好），需人工校准。

### 6.3 RLHF 与 PPO（Q86）：完整流程

1. **SFT**：先训练一个会"说人话"的策略模型；
2. **训练 Reward Model（RM）**：对同一 prompt 的多个回答打分，从人类偏好对学习；
3. **PPO 优化策略**：策略生成回答 → RM 打分 → 用 PPO 更新策略，同时加 **KL 惩罚**约束策略别离 SFT 太远。

**为什么需要 KL 惩罚**：reward model 不是完美代理，策略会钻 RM 的空子（reward hacking）；KL 惩罚让策略停留在"人类会认可的语言分布"附近，相当于给优化加了护栏。

**PPO 在 LLM 里的关键组件**：actor（策略）、critic（价值网络估计优势）、clip 目标（限制单步更新幅度防止崩坏）、GAE（优势估计）。**难点**：训练不稳定、在线采样成本高、RM 有偏。

### 6.4 DPO（Q87）：把 RL 变成监督学习

**为什么 DPO 更简单**：PPO 需要显式 RM + 在线采样 + RL 训练；DPO 从偏好对（chosen/rejected）直接学习，**损失等价于隐式 reward 下的 Bradley-Terry 分类损失**，把 RL 优化变成监督式 loss。

**DPO 的直觉**：让 chosen 的回答在策略下概率更高、rejected 更低，且用参考模型（SFT）做锚点，隐式地约束偏离。

**代价（面试要主动说）**：对偏好数据质量极敏感、容易过拟合偏好；无法引入"在线探索"，复杂多轮场景仍需要 RL；对"偏好噪声"鲁棒性弱。

🎯 迁移：简历里的翻译 PPO 项目，被问 DPO 时先讲区别、再讲你当时为什么选 PPO（可在线反馈、reward 可定义如 BLEU/人工评分）。

### 6.5 Reward Hacking（Q88）：模型钻奖励空子

**是什么**：模型为了拿高分，学会迎合 reward model 的"表面特征"而偏离真实目标：输出冗长、讨好、套模板、钻规则空子（如只按关键词作答）。

**为什么会发生**：RL 的优化目标是代理指标（RM 分数），不是真实目标；RM 总有可被利用的偏差，且 RL 会把这种偏差放大到极致。

**缓解**：KL 约束；reward 模型鲁棒化（更多人类标注、多维度打分）；reward 组合/多样性；人工抽检与红队；与真实业务指标对齐（线上 AB 验证而非只看 RM 分数）。

### 6.6 幻觉（Q89）：类型与抑制

**类型**：事实错误（编造不存在的事实）、忠实度不足（编造引用/数字）、逻辑不一致、知识过期。

**降低手段（从系统到模型）**：
- **RAG 提供证据** + 要求模型只依据给定素材作答（引用约束）；
- **结构化输出**：结论 + 证据片段 + 置信度，低置信拒答；
- **检索校验**：用 NLI/校验模型判断结论是否被证据支持；
- **后训练**：SFT/RL 用"拒答/承认不知道"样本对齐；
- **采样控制**：温度调低、约束解码。

**机审中幻觉尤其危险**：证据定位错误会直接导致错杀/漏杀，所以审核链路里"证据先行、结论后置"是硬要求。

### 6.7 模型量化（Q90）：INT8/INT4 的影响

**是什么**：把 FP32/FP16 的权重/激活用低比特表示，降低显存与推理成本。常见方法：GPTQ（基于 Hessian 的二阶量化）、AWQ（按激活幅度保护敏感通道）、GGUF（CPU/小显存部署）。

**影响**：模型体积缩小约 4 倍（INT4）、吞吐提升，但可能有精度损失；**为什么高敏感任务要评测**：量化误差在长尾/边界样本上可能放大，必须用校准集评估准召后再上线。

**机审分层**：初筛可用量化小模型；复杂复核用高精度或更大模型——正好呼应 Q101 的分层思想。

### 6.8 vLLM 与 PagedAttention（Q91）：高并发推理为什么快

- **Continuous Batching**：请求动态进出批次，不等固定 batch 凑满，吞吐显著提升；
- **PagedAttention**：把 KV Cache 按固定大小的"页"分块管理，减少显存碎片与浪费（传统方式预分配 max length 导致大量闲置）；支持页面共享（beam search/并行采样复用）；
- 其他：算子融合、量化、prefix caching（相同前缀的 KV 复用）。

**机审场景**：高 QPS、长短混合请求，vLLM 是标配；追问"为什么不用普通 transformers 推理"→ 因为 naive 实现每请求独占显存、批处理不动态。

### 6.9 LoRA（Q92）：原理与超参

**原理**：冻结原权重 W，学习低秩增量 ΔW = B·A（B 是 d×r、A 是 r×d，r 远小于 d），前向变成 Wx + BAx；推理时把 W + BA 合并，**零额外推理延迟**。

**为什么低秩可行**：预训练模型微调时的参数变化集中在一个低秩子空间，不需要更新全参数。

**关键超参**：
- r（秩）：越大容量越高但过拟合风险↑，常见 8–64；
- alpha：缩放因子，实际缩放为 alpha/r，决定 LoRA 分支强度；
- target modules：Q/K/V/O 投影、FFN，选哪些模块影响效果与成本；
- dropout：LoRA 分支上防止过拟合；
- 学习率：通常比全参微调大。

**为什么省显存**：只优化增量参数，优化器状态（Adam 的 m/v）占用大幅下降；QLoRA = 基座 4bit 量化 + LoRA，进一步省显存。

### 6.10 灾难性遗忘（Q93）

**是什么**：模型学新任务后旧能力退化（新任务梯度覆盖旧任务分布）。

**解法**：
- **数据配比**：混合通用数据与领域数据（如机审 SFT 里 1:4 到 1:10 的通用:领域比例）；
- **回放（replay）**：训练时混入旧任务代表性样本；
- **LoRA/适配器**：增量参数天然隔离新旧任务；
- 正则、课程学习、多任务训练。

**机审场景**：既要提升新违规类别召回，又要保留通用语义理解，数据配比 + LoRA + 回归评测（旧类别的准召不回退）是关键。


### 6.11 如何评估一个 LLM（Q94）：通用与机审两套口径

- **通用能力**：MMLU（知识）、C-Eval（中文）、HumanEval（代码）、GSM8K（数学）、BBH（推理）。
- **业务能力**：golden set（固定评测集）、标签准确率、P/R/F1/AUC、人审一致率、证据命中率、badcase 率、成本/延迟。

**机审 eval 流程**：固定评测集 → 多模型/多版本对比 → 分层分析（按违规类别、置信度区间、业务线）→ 线上小流量 AB。

**机审特别要测什么**：低置信样本、边界 case、新违规变体、图文不一致——因为这些地方才是准召损失的高发区。

🎯 迁移：简历里"评估集构建、chunking 评测"要能讲出分层分析，例如"按章节类型分层看长文本一致性"，而不是只有一个总准确率。

### 6.12 长上下文与 RoPE 外推/插值（Q95）

**为什么长上下文难**：自注意力 O(n^2) 计算/显存成本；位置编码在训练长度外表现崩坏（外推）。

**训练阶段手段**：更长序列预训练/继续训练、稀疏注意力（窗口 + 全局）、FlashAttention 降低显存。

**推理阶段手段（针对 RoPE）**：
- **位置插值（PI）**：把超出训练长度的位置按比例压缩回训练范围；
- **NTK-aware 缩放**：只缩放高频频率，保留低频外推能力，短序列不损失；
- **YaRN**：NTK + 注意力温度校正，进一步改善。

**核心思想一句话**：让长序列的位置编码在训练长度外仍保持稳定，避免注意力分数分布崩坏。🎯 简历长文本生成（章节状态、记忆检索）项目可以直接把这一节当答案。

### 6.13 Function Calling / Tool Use（Q96）

**是什么**：模型按工具 schema 输出"工具名 + 参数"，系统执行工具并把结果回填到上下文，模型继续生成。关键在"模型决策、系统执行、结果回填"的闭环。

**和 RAG 的关系**：RAG 可以看成"一个 retrieval 工具"；工具化之后检索、查库、调模型都能统一编排。

**机审 Agent 里的工具**：查黑名单库、查商品信息、查历史违规记录、调 OCR/图像模型、查政策条款、调证据检索——都用 tool use 编排，每个工具输出结构化结果供下一步决策。

**易错点（面试主动讲）**：schema 必须严格（JSON 校验）、工具超时与重试、参数注入与安全（工具调用的输入也要鉴权与防注入）、结果超长截断。

### 6.14 MCP（Q97）：为什么 Agent 要标准化工具

**是什么**：Model Context Protocol，开放协议，标准化"模型应用 ↔ 外部数据源/工具"之间的连接：工具发现（tools/list）、调用（tools/call）、资源（resources）、提示（prompts）。

**为什么用**：
- 工具即插即用：服务方实现一次 MCP Server，任何 MCP 客户端都能用；
- 统一鉴权、生命周期、上下文管理，避免每个 Agent 重复集成；
- 生态复用：数据库、文件系统、浏览器、内部系统都有现成 Server。

🎯 迁移：简历的 Autono 支持 MCP，面试就答"我们把工具从硬编码改成 MCP 协议，新增工具不再改 Agent 主代码，只注册 Server"。

### 6.15 ReAct（Q98）：Reason + Act 交替

**是什么**：Thought（思考）→ Action（调工具）→ Observation（观察结果）→ Thought… 循环，直到给出 Final Answer。

**比纯 CoT 好在哪**：CoT 只有"想"，无法获取外部信息、无法执行动作、无法纠错；ReAct 让推理与行动互相校正，适合需要检索/计算/多步操作的任务。

**失效模式（面试必答）**：循环发散（反复调同一个工具）、上下文无限增长、工具错误被当作事实。**缓解**：step budget（最大步数）、循环检测（相同调用去重/告警）、结果校验、轨迹日志。

### 6.16 多 Agent 协作（Q99）：机审里怎么拆

**模式**：编排者-执行者（orchestrator-worker）、流水线（pipeline）、辩论/反思（debate/reflection）、层级（hierarchy）。

**机审拆分**：召回/初筛 Agent → 违规识别 Agent → 证据抽取 Agent → 政策匹配 Agent → 复核 Agent。

**为什么拆**：职责单一、prompt 更聚焦、每个环节可独立评测与迭代。**代价**：延迟叠加、成本上升、误差传递。

**如何避免误差传递（关键）**：
- 各 Agent **共享原始证据**而非只共享结论（让下游能复核上游）；
- 不确定性阈值：低置信不硬决策，转人审；
- 复核 Agent 有权推翻上游；
- 记录每步轨迹（trajectory）供归因。

### 6.17 LLM 的 badcase 归因（Q100）：分层拆解

1. **分层拆解**：输入问题 / 知识缺失 / 指令理解 / 生成偏差 / 评测错误——先定性是哪一层；
2. **取证据**：看 prompt、检索结果、logits/置信度、输出结构、工具轨迹；
3. **统计高频失败模式**：按类别聚合，按频次 × 业务损失排序定优先级；
4. **对症修复**：数据、prompt、RAG、SFT/RL 分别处理，并回测**不回归**（旧 case 复跑）。

**面试怎么答**：用"机审误杀/漏杀"举例——漏杀先看是召回没召回（检索/初筛层）还是识别错（模型层）还是标签错（评测层），再决定补数据还是调阈值。


## 七、机审业务链路与多模态（对标 Q101–Q116）

### 7.1 为什么是"规则 + 小模型 + 大模型"组合（Q101）

**不是大模型打天下**，原因四条：

- **成本**：高 QPS 下大模型推理成本线性增长，全量上大模型 ROI 是负的；
- **延迟**：广告/电商审核有时效要求，链路必须快；
- **可解释**：规则与树模型决策路径可审计，申诉场景需要"为什么拒绝"；
- **稳健**：规则兜底已知确定性风险，大模型处理开放语义。

**分层分工**：规则处理确定性违规 → 小模型高吞吐初筛 → 大模型只处理低置信/高风险/边界样本 → 人审兜底。**这就是机审的"金字塔"结构**：越往上越贵越准，越往下越便宜越快。

### 7.2 多模态审核的常见架构（Q102）

- **单流（early fusion）**：文本/图像 token 直接拼接进统一 Transformer，语义交互充分，但计算贵；
- **双塔（late fusion）**：各模态独立编码，再做对齐/融合（分类、检索），吞吐高；
- **视觉语言模型（VLM）**：视觉编码器 + 投影层 + LLM 推理，能做开放语义判断与证据定位；
- **视频**：抽帧 + 时序建模 + OCR/ASR + 关键帧摘要，多模态证据融合。

**图文不一致为什么难**：单模态模型各自"看不见"对方模态的违规信号（如正常图 + 违规文案），必须联合建模或跨模态校验（CLIP 匹配分）。

### 7.3 视频审核如何平衡成本与召回（Q103）

- **抽帧策略**：关键帧、镜头边界检测、画面变化度（SSIM/直方图差异）决定抽帧密度——静止场景少抽、动作/镜头切换多抽；
- **级联**：轻量模型先扫全片，只有可疑片段送大模型；
- **证据融合**：画面 + 字幕 + 音频三路信号，违规信号常跨模态（口播 + 画面）；
- **分片并行**：切段并行推理，汇总决策，避免全片一次长序列推理（成本/延迟都省）。

**回答公式**：抽帧密度 × 级联路由 × 多模态证据 × 并行分片 = 在召回不降的前提下压成本。

### 7.4 图文不一致的解法（Q104）

1. 单模态都会漏，必须**图文联合**或**跨模态校验**；
2. **证据定位**：要求模型输出图片证据框/时间戳 + 文本理由，倒逼模型"真看了图"；
3. **训练数据**：构造"正常图 + 违规文 / 违规图 + 正常文"的负样本，专门训练不一致检测；
4. **人审辅助**：自动高亮可疑区域，降低人审定位成本、提升效率。

### 7.5 隐晦黑话/变异文本（Q105）

- **规则泛化**：同音（数字谐音）、拆字、符号替换（空格/emoji 插入）、拼音、大小写混淆 → 先做归一化再匹配；
- **语义模型**：预训练 + 领域 SFT，样本覆盖黑话变体，靠语义而非关键词抓；
- **黑话词典**：动态更新、版本化，避免误杀（词典命中要能回滚）；
- **图网络**：关联黑产账号/群组，从"同一团伙共用新变体"中发现新黑话。

**易错点**：归一化不能过度（会把正常文本也匹配上），需要"词典 + 语义 + 上下文"三重确认。

### 7.6 机审全链路（Q106）：画图 + 讲七步

**画法（面试直接画）**：

1. **业务接入**：内容进队，带业务类型、优先级、风控上下文；
2. **规则前置**：黑名单、关键词、资质校验，确定性违规直接拦截；
3. **模型初筛**：文本/图像/视频多模态打分，输出违规类别 + 置信度；
4. **策略路由**：高置信自动通过/拒绝，低置信或高风险转人审；
5. **人审复核**：人审结果作为最终决策，并回流标注；
6. **申诉与纠偏**：商家/用户申诉 → 二次复核 → 纠正模型与策略；
7. **监控与迭代**：线上准召、时效、成本、badcase 率驱动下一轮优化。

**讲链路的口径**：每个环节都要说出"输入、输出、指标、兜底"，不要只背流程。

### 7.7 机审、人审、申诉三线配合（Q107）

- **机审**：高通量、低成本、统一标准，负责确定性风险与初筛；
- **人审**：处理边界、高风险、争议样本，输出高质量标注回流；
- **申诉**：保护体验，收集模型误杀信号，作为负样本回流。

**核心观点**：不是取代人，而是**让人只处理最有价值的样本**——自动决策率提升的同时，人审单价（每单时间）也要下降，这才是 ROI。

### 7.8 置信度分级路由与阈值（Q108）

**双阈值路由**：模型输出违规概率 p，设 t_low < t_high：

- p >= t_high：自动拒绝；
- p <= t_low：自动通过；
- 中间：转人审。

**阈值怎么定（为什么）**：阈值本质是在"漏杀损失、误杀损失、人审成本"三者之间找总成本最低点。做法：用历史数据在 P/R 曲线上找工作点，对每个候选 (t_low, t_high) 回测总成本 = 漏杀损失 + 误杀损失 + 人审成本，选最小。

**易错点**：t_low 与 t_high 之间的"人审区间"越大，人审量越大；区间太小则边界样本自动决策错误率高——两个阈值不是对称的，取决于业务对误杀/漏杀的相对厌恶。

### 7.9 线上指标（Q109）：最看哪三个

- **质量**：Precision、Recall、F1、AUC、badcase 率、人审一致率；
- **效率**：自动决策率、人审量、平均人审时长、时效（P95 审核时长）；
- **成本**：单条成本、GPU/API 成本、人审成本；
- **体验**：误杀率、申诉率、申诉通过率。

**最看哪三个（给出你的答案与理由）**：高置信自动决策区间的 Precision（误杀风险）、高危类别的 Recall（漏杀风险）、单条成本（ROI）。因为这三者直接决定"这个系统值不值得运转"。

### 7.10 误召回突然上升怎么排查（Q110）：六步排查法

1. **确认口径**：先排除统计口径/报表 bug（同环比定义、数据延迟）；
2. **拆维度**：哪类业务、哪类违规、哪个模态、哪个模型版本、哪个阈值区间；
3. **抽检 badcase**：是真误杀、标签错误，还是新内容形态（模型没见过）；
4. **查漂移**：节假日、新活动、新商品、新黑产导致数据分布变化；
5. **修复**：阈值回调、规则豁免、补训、灰度回滚——按影响面从小到大；
6. **复盘**：补监控与告警（按维度分桶监控准召），避免下次后知后觉。

**为什么先确认口径**：线上指标异常里相当一部分是口径/报表问题，先排除再动模型，避免瞎改。

### 7.11 突发高危内容应急（Q111）

1. **先止血**：立即上确定性规则/黑名单，不依赖模型（规则可回滚、可解释）；
2. **回溯**：召回历史相似内容，批量复核；
3. **人审专项**：提高优先级和时效，集中处理；
4. **事后训练**：构造新风险样本，SFT/RL 补齐召回；
5. **预案化**：责任人、SOP、灰度、回滚、上报、复盘——把应急变成流程。

**面试加分点**：强调"规则先上、模型后补、全程留痕"，并主动提"这类事件的 KPI 应该看漏杀响应时间而不是常规准召"。

### 7.12 为什么误杀也不能随便放松（Q112）

误杀 = 商家损失、创作者流失、用户体验伤害，长期侵蚀平台供给与增长。**治理目标是在总成本最低点平衡**：高风险优先召回（宁误杀不漏杀），低风险优先精准（宁漏杀不误杀），并用申诉通道快速纠错。

**一句话总结**：安全不是"越严越好"，而是"在该严的地方严、在该松的地方松"，且每个决策都能申诉。

### 7.13 离线 F1 高、上线差（Q113）：原因清单

- **数据分布漂移**：离线集不代表线上（时间、人群、内容形态）；
- **标签/数据泄漏**：离线虚高；
- **阈值/后处理未对齐**：离线评测用的阈值与线上不一致；
- **输入差异**：线上缺少多模态/上下文信息，模型输入不同；
- **延迟/资源降级**：线上超时截断、模型降级；
- **评测集过小或过拟合**：离线指标方差大。

**解法**：线上抽检 + AB + 分层监控 + 持续回流标注，形成"离线验证 → 线上验证 → 回流"闭环。

### 7.14 badcase 闭环设计（Q114）

1. **收集**：人审纠错、申诉、抽检、用户举报；
2. **归类**：漏杀 / 误杀 / 标签错 / 边界 / 新风险；
3. **归因**：数据、prompt、知识、模型、策略、评测——定位到具体层；
4. **修复**：补数据、SFT/RL、RAG、规则、阈值；
5. **验证**：离线回测 + 线上小流量 AB；
6. **监控**：指标变化、是否引入回归（旧 badcase 复跑）。

**为什么闭环比单次优化重要**：内容形态和黑产持续演化，没有回流机制的系统会随时间退化。

### 7.15 一次模型迭代是否值得上线（Q115）

- **定主指标**：如"高危召回 @ 固定误杀率"；
- **定护栏指标**：成本、延迟、申诉率（主指标提升但护栏恶化要谨慎）；
- **离线**：golden set + 历史回放（用历史线上数据回测）；
- **线上**：小流量 AB，观察主指标提升、护栏不恶化；
- **决策**：提升是否超过成本；是否可解释；是否可回滚。

**一句话**：上线 = 主指标显著提升且护栏不恶化且可回滚，三者缺一不可。

### 7.16 治理与增长冲突（Q116）

先区分风险等级：高风险零容忍；中低风险用阈值和分层，允许申诉与差异化策略，不一刀切。用数据算清"误杀损失 vs 漏杀损失"，把取舍做成可量化决策，并把业务方拉进同一个指标体系，避免"安全要召回、增长要流量"各说各话。

**面试怎么收尾**："我反对拍脑袋严/松，主张用 AB 和成本模型做裁决，同时给业务留申诉出口。"


## 八、RAG 与知识管理（对标 Q117–Q121）

### 8.1 机审里 RAG 用在哪（Q117）

- **政策/规则问答**：审核员查最新标准，替代翻文档；
- **证据检索**：从商品描述、图片、历史记录检索证据；
- **案例库**：相似历史 case 作为 few-shot 示例；
- **知识注入**：行业准入、黑话词典、法律法规。

**为什么机审需要 RAG 而不是全量塞进 prompt**：政策与黑话高频更新、知识量超过上下文窗口、且需要"证据可溯源"（申诉时要能指出依据哪条规则）。

### 8.2 RAG 运维路径（Q118）

1. **文档接入**：解析（PDF/HTML）、切分（chunking + overlapping）、OCR、元数据（来源、版本、生效时间）；
2. **索引**：embedding + 向量库 + 关键词/BM25 混合检索；
3. **召回**：检索 → 重排 → 过滤；
4. **生成**：把证据拼入 prompt，要求引用来源；
5. **评测**：检索命中率、答案忠实度、引用正确率；
6. **运维**：日志、badcase、知识更新、过期清理。

**切分为什么重要（知其所以然）**：chunk 太大 → 语义稀释、超过模型上下文；chunk 太小 → 上下文碎片化、丢失关联；overlapping 保证跨 chunk 的语义不丢。chunk 粒度要和"检索单元"与"生成单元"对齐。

### 8.3 知识过期/规则变更（Q119）

- 文档带生效时间/版本号，过期自动下线；
- 定期对账：用新政策 vs 旧知识测试冲突；
- 双写/灰度：新知识先并行验证再切换；
- 日志追踪答案引用，方便回溯。

**核心**：知识是有生命周期的资产，必须版本化 + 可回滚 + 可追溯，和代码一样管理。

### 8.4 embedding 与 rerank 怎么选（Q120）

- **初筛**：向量召回 + BM25 混合，保证召回（宁多勿漏）；
- **重排**：Cross-Encoder（query 与 doc 拼接打分）或 LLM rerank，提升精度；
- **为什么混合**：向量擅长语义相似、BM25 擅长精确词匹配（政策条款、黑话词），互补；
- **选型看**：延迟、QPS、语料规模、领域数据——机审高召回优先，初筛宁多勿漏，重排再精准。

### 8.5 RAG 幻觉/引用错误（Q121）

- 生成前只给 top-k 证据并截断；
- 强制结构化输出：结论 + 证据片段 + 置信度；
- 用 NLI/校验模型判断结论是否被证据支持（忠实度校验）；
- 低置信转人审，不强行给结论。

**机审红线**：RAG 输出必须能溯源，找不到证据宁可拒答，也不能编。

## 九、Agent / Workflow / Harness（对标 Q122–Q126）

### 9.1 auto-Workflow 设计（Q122）

**是什么**：把任务拆成可配置、可插拔的节点 DAG，节点可以是规则、模型、工具、人审。

**审核 Workflow 怎么设计**：召回 → 识别 → 证据抽取 → 政策匹配 → 决策 → 路由。每个节点：

- 输入/输出是结构化 JSON（方便审计与归因）；
- 带超时、重试、降级；
- 状态机控制流转，异常有兜底（如转人审）。

**为什么结构化中间结果重要**：每个节点输出可追溯，badcase 归因时能定位到"哪个节点错了"。

🎯 迁移：简历的 Autono/EasyHarness 就是 Workflow + Harness 的直接对应，讲"节点可配置、轨迹可审计、评测可回放"。

### 9.2 multi Agents 分工与误差传递（Q123）

**分工**：识别 Agent 输出违规类别，证据 Agent 定位证据，复核 Agent 独立复核，政策 Agent 匹配条款。

**避免误差传递（四条铁律）**：
1. 各 Agent **共享原始证据**，不只共享结论；
2. 设置不确定性阈值，低置信不硬决策；
3. 复核 Agent 有权推翻上游；
4. 记录每步轨迹，出问题能回溯。

### 9.3 Harness（Q124）：机审 Harness 要具备什么

**是什么**：统一的模型/策略评测与实验框架，管理数据、prompt 版本、模型适配、指标计算、报告、对比、回归、线上回放。

**机审 Harness 特别需要**：混淆矩阵、分层指标（按业务线/违规类别/置信度区间）、成本与延迟、badcase 分析、AB 对接。

🎯 迁移：简历的 EasyHarness 直接命中——讲"从数据集 → 跑测 → 指标 → 报告 → 回归"一条链，并强调分层指标和线上回放。

### 9.4 Agent 可靠性保障（Q125）

- 输入/输出 schema 校验（结构化输出，解析失败即重试）；
- 工具调用失败重试、超时、降级；
- step budget、循环检测、终止条件；
- 关键决策低置信转人审；
- 全链路 trace 与日志；
- 评测 trajectory 成功率，而非只看最终答案。

**为什么看 trajectory**：最终答案对，但过程绕了 20 步、调了 5 次错误工具——这种 Agent 上线后成本与失败率都不可控。

### 9.5 为什么 demo 漂亮、上线就崩（Q126）

- demo 样本少、环境固定、人工兜底不可见；
- 上线后：工具返回脏数据、异常流、长链路误差累积、上下文超限；
- 缺乏可观测性与失败恢复。

**解法**：从"追求灵巧"转向"追求可预测"——用工作流约束 + 状态机 + 灰度 + 监控，把失败变成可恢复、可归因的事件。


## 十、SQL 数据分析（对标 Q130–Q137）

> 机审岗位的 SQL 考的是"聚合 + 窗口函数 + 条件逻辑"，不是复杂调优。先掌握四个原子能力：GROUP BY 聚合、CASE WHEN 条件计数、窗口函数（ROW_NUMBER / AVG OVER）、连续问题（行号差）。

### 10.1 每日审核量与拒绝率（Q130）：GROUP BY + CASE WHEN

```sql
SELECT
    biz_type,
    dt,
    COUNT(*) AS audit_cnt,
    SUM(CASE WHEN decision = 'reject' THEN 1 ELSE 0 END) AS reject_cnt,
    SUM(CASE WHEN decision = 'reject' THEN 1 ELSE 0 END) / COUNT(*) AS reject_rate
FROM audit_log
GROUP BY biz_type, dt
ORDER BY biz_type, dt;
```

**为什么这样写**：`COUNT(*)` 是总行数；`SUM(CASE WHEN ... THEN 1 ELSE 0 END)` 是"满足条件的行数"——条件聚合是 SQL 高频套路，等价于"按条件计数"。

### 10.2 3 日移动平均（Q131）：窗口函数 ROWS BETWEEN

```sql
SELECT
    dt,
    audit_cnt,
    AVG(audit_cnt) OVER (ORDER BY dt ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS ma3
FROM (
    SELECT dt, COUNT(*) AS audit_cnt
    FROM audit_log
    GROUP BY dt
) t
ORDER BY dt;
```

**要点**：窗口函数的"窗口"用 `ROWS BETWEEN ... AND ...` 定义；`2 PRECEDING` = 前两行。**为什么子查询**：先按天聚合出每日量，再对聚合结果做窗口计算——窗口函数不能和 GROUP BY 的普通列混用（除非按分组键分区）。

### 10.3 TopN（Q132）：ROW_NUMBER + 子查询

```sql
SELECT reviewer_id, appeal_win_cnt
FROM (
    SELECT
        reviewer_id,
        COUNT(*) AS appeal_win_cnt,
        ROW_NUMBER() OVER (ORDER BY COUNT(*) DESC) AS rk
    FROM audit_log
    WHERE appeal_result = 'win'
    GROUP BY reviewer_id
) t
WHERE rk <= 3;
```

**为什么用子查询**：WHERE 不能直接引用窗口函数（SQL 执行顺序：WHERE 先于窗口计算），必须包一层子查询再过滤。**为什么 ROW_NUMBER 而不是 RANK**：ROW_NUMBER 给唯一名次（并列也占位）；RANK 允许并列且跳过名次；DENSE_RANK 允许并列不跳过。按需求选。

### 10.4 模型误杀率（Q133）：条件聚合比值

```sql
SELECT
    model_version,
    SUM(CASE WHEN model_decision = 'reject' AND human_decision = 'pass' THEN 1 ELSE 0 END)
        / NULLIF(SUM(CASE WHEN model_decision = 'reject' THEN 1 ELSE 0 END), 0) AS false_positive_rate
FROM audit_log
GROUP BY model_version;
```

**为什么 NULLIF**：分母可能为 0（该模型从未判拒绝），直接除会报错/返回 NULL；NULLIF(x, 0) 把 0 变 NULL，除法结果 NULL 表示"无样本"，比报错好。这就是 Q133 定义的"模型判违规但人审驳回"的误杀率。

### 10.5 连续 3 天超阈值（Q134）：行号差分组——最难也最常考

```sql
SELECT DISTINCT biz_type
FROM (
    SELECT
        biz_type,
        dt,
        audit_cnt,
        ROW_NUMBER() OVER (PARTITION BY biz_type ORDER BY dt)
            - DENSE_RANK() OVER (PARTITION BY biz_type, CASE WHEN audit_cnt > 10000 THEN 1 ELSE 0 END ORDER BY dt) AS grp
    FROM (
        SELECT biz_type, dt, COUNT(*) AS audit_cnt
        FROM audit_log
        GROUP BY biz_type, dt
    ) a
) b
WHERE audit_cnt > 10000
GROUP BY biz_type, grp
HAVING COUNT(*) >= 3;
```

**原理（知其所以然）**："连续"的本质是"日期是相邻的"。技巧：对每个业务线按日期排序编号（ROW_NUMBER），再按"是否超阈值"分区的编号（DENSE_RANK）——**两者的差 grp 在连续超阈值段内是同一个常数**（因为日期连续时两个编号同步递增），断档处编号错开。然后按 (biz_type, grp) 计数 >= 3 就是连续 3 天。

面试先说思路再写：① 按天聚合 ② 超阈值打标 ③ 行号差找连续段 ④ 计数过滤。

### 10.6 分位数 P95（Q135）

```sql
-- Hive/Spark
SELECT APPROX_PERCENTILE(handle_seconds, 0.95) AS p95_seconds
FROM audit_log;

-- MySQL 8 无内置近似分位数，用窗口函数近似：
SELECT DISTINCT
    PERCENTILE_CONT(0.95) WITHIN GROUP (ORDER BY handle_seconds) OVER () AS p95_seconds
FROM audit_log;
```

**为什么用 P95 而不是平均时长**：平均对极端值敏感（个别超长单拉高均值），P95 表示"95% 的审核在多少秒内完成"，更贴近真实体验与 SLA。**答法**：先问清指标口径（按单还是按批次、含不含排队时间）。

### 10.7 Pandas 等价实现（Q136、Q137）

```python
import pandas as pd

# Q136：每日拒绝率（等价于 SQL GROUP BY + 条件聚合）
df = pd.read_sql("SELECT biz_type, dt, decision FROM audit_log", conn)
df["is_reject"] = (df["decision"] == "reject").astype(int)
out = df.groupby(["biz_type", "dt"]).agg(
    audit_cnt=("is_reject", "count"),
    reject_rate=("is_reject", "mean"),
).reset_index()

# Q137：百万级日志按业务线分块统计（chunked，防止内存爆）
chunks = pd.read_csv("audit_log.csv", chunksize=200_000)
res = {}
for df_chunk in chunks:
    for biz, g in df_chunk.groupby("biz_type"):
        res[biz] = res.get(biz, 0) + len(g)
```

**为什么分块**：百万行全量进内存可能 OOM；`chunksize` 流式读取 + 增量聚合，内存恒定。**易错点**：`reject_rate = mean(is_reject)` 的前提是 is_reject 是 0/1 数值——这正是"平均值即比例"的技巧。

### 10.8 SQL 回答方法论

1. **先翻译需求**：确定表、分组键、过滤条件、输出字段；
2. **先写骨架**：SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY 的执行顺序（FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY），哪里能引用别名、哪里不能，都从这里推；
3. **窗口函数不能用在哪**：WHERE 和同层 GROUP BY 的聚合列；
4. **说清楚口径**：去不去重、时间窗口边界（左闭右开）、NULL 处理；
5. **先给正确结果，再提优化**：面试先跑通，再说索引/分区/避免全表扫描。


## 十一、经营思维、ROI 与开放题（对标 Q127–Q129、Q138–Q142）

### 11.1 准确率提升 1%、成本提升 50%，上不上（Q127）

**标准答案：不上，除非这 1% 全落在高危漏杀且业务损失远大于成本。**

理由：accuracy 不是决策指标。先拆成 P/R 看提升落在哪：如果是低危类别的 Precision 提升，业务价值≈0；如果是高危漏杀下降，才值得算账。再算 ROI：减少的漏杀损失 + 节省的人审成本 vs 增加的单条成本。

**话术**："我不用 accuracy 决策，用『高危召回 @ 固定误杀率』+ 单条成本做决策。"

### 11.2 机审系统 ROI 估算（Q128）

```
ROI ≈ (节省人审成本 + 减少业务损失) / (模型/工程/运维成本)
```

- **节省人审成本** = 自动决策比例 × 人审单价；
- **减少业务损失** = 漏杀减少带来的赔付/监管/用户损失下降；
- **成本** = GPU/API、数据标注、工程、运维。

**关键假设要写清**：人审单价、误杀损失、漏杀损失——这些假设决定了结论，面试要主动说出来"我的估算是基于这三个假设，任何一个变了结论要重算"。

### 11.3 大小模型按 ROI 分层（Q129）

- 高频简单 → 规则/小模型（最便宜）；
- 中频中等 → 小模型 + 特征；
- 低频复杂/高风险 → 大模型/人审。

**分层点怎么定**：用历史流量分布 × 各层错误成本算总成本曲线，找最低点；分层阈值动态调整（新风险出现时把更多样本送大模型）。

### 11.4 广告"夸大宣传"边界（Q138）

1. **把政策拆成可判定子项**：绝对化用语（最、第一、国家级）、无法证明的效果承诺、对比贬低、虚假资质——边界从"语义"变成"可核查清单"；
2. **构造正负样本**：标注**证据片段**而不是只给标签（模型要能指出违规点）；
3. **让模型输出**"违规点 + 证据 + 适用条款 + 置信度"；
4. **边界样本持续人审回流**，形成案例库，案例库同时喂 RAG 和训练集。

**为什么"证据片段"标注关键**：让模型从"感觉违规"变成"依据条款违规"，可解释性直接决定申诉处理成本。

### 11.5 电商图片正常但标题违规（Q139）

- 文本模型抓标题/详情，图像模型抓图片，**融合层做联合决策**；
- 要求模型输出"证据模态"（是标题还是图片），防止只看到图就通过；
- 训练"图文不一致"负样本：正常图 + 违规标题、违规图 + 正常标题。

**本质**：这是 Q104 图文不一致问题的电商版，答案通用。

### 11.6 生活服务资质过期/伪造（Q140）

1. **OCR/信息抽取**：从证照提取主体、有效期、编号；
2. **校验**：与工商/平台数据比对，识别 PS、过期、主体不一致；
3. **规则 + 模型 + 人审**：确定性规则（过期/编号格式）直接拦，可疑转人审；
4. **图网络**：识别"同一资质多账号复用、同一主体频繁换证"等黑产关联。

### 11.7 AB 实验评估新策略（Q141）

- **分流**：按内容/商家稳定 hash 分流，保证同质（同一内容不会同时出现在两个桶）；
- **指标**：主指标（高危召回/误杀率）+ 护栏（人审量、成本、时效、申诉率）；
- **时长**：覆盖足够样本与业务周期（至少覆盖一个业务波动周期，如 7 天）；
- **决策**：显著提升且护栏不恶化才全量；异常可回滚。

**追问点**：样本量怎么估——用历史指标方差做功效分析；桶间是否公平——用 SRM（样本比例失配）检验。

### 11.8 新违规类别零样本怎么快速上线（Q142）

1. **规则先行**：关键词/正则/黑名单先拦截确定性 case，先止血；
2. **Few-shot**：从人工确认的少量样本里挑示例，LLM 直接分类（ICL）；
3. **检索增强**：相似历史案例召回拼进 prompt；
4. **主动学习**：选最不确定/最有信息量的样本给人标，快速攒训练集；
5. **迭代**：先 SFT，稳定后 RL 优化，全程规则兜底。

**为什么是这个顺序**：先确定性、再模型、再数据——每个阶段都有兜底，不裸奔。


## 十二、HR 面与价值观（对标 Q143–Q154）

> HR 面不是"聊天"，是在验证三件事：**你是否好协作、是否结果导向、是否有边界感**。每条回答都按"观点 + 例子 + 可验证结果"三段式。

### 12.1 跨团队项目管理（Q143）

**答法**：先对齐目标、负责人、交付物、时间点；用文档写清问题定义、指标、里程碑、风险与依赖；执行中定期同步、把阻塞升级；上线前明确验收标准、上线后复盘。**关键句**："让算法、产品、运营、人审用同一套指标说话。"

### 12.2 产品说太严、安全说太松（Q144）

**不站队，先量化**：把"太严/太松"翻译成误杀率、申诉率、漏杀率、高危曝光率；拉三方对齐风险等级与业务价值；用分层策略：高风险从紧、低风险给申诉与差异化；最后用 AB 验证让数据做裁决。

### 12.3 项目要不要做（Q145）

看业务价值、可验证性、资源投入、风险。**优先做高频、高损失、可快速闭环的项目**；价值大但不清晰 → 先小范围试点验证假设再放大。

### 12.4 你在团队里的角色（Q146）

**答法**："偏执行到 owner 的中间态：能独立拆解和推进，也愿意写文档、做复盘；边界不清时主动提方案，重大决策升级，不擅自扩大范围。"——对应简历里"从 0 到 1 搭建后训练链路"的经历。

### 12.5 最有成就感的一件事（Q147）

**模板**（结合简历改数据）："不是某个准确率，而是把长文本生成从不可控变成可运营：建立了章节状态、记忆检索和一致性校验，最终支撑月产 500 本。它让我理解：模型能力只有被工程化和流程化，才能变成业务结果。"

**为什么这个故事好**：有目标（不可控→可运营）、有手段（状态/检索/校验）、有结果（月产 500 本）、有反思（工程化思维），四要素齐全。

### 12.6 压力最大的一次（Q148）

**模板**：deadline 紧、依赖并行、效果不稳定 → 按优先级和依赖拆任务、砍非必要需求、先跑最小闭环、每天同步风险 → 按时交付 → 复盘发现"早期需求边界不清是压力源头"，此后强制开工前确认范围。

**得分点**：复盘落到"流程改进"而不是"我抗压能力强"。

### 12.7 owner 意识（Q149）

"不是把所有事做完，而是对结果负责：主动定义问题、协调资源、暴露风险、跟进上线与复盘。即使某部分不是我做的，也会确认它不影响最终结果。"

### 12.8 内容安全价值观（Q150）

"安全是底线，不是可选项。技术手段服务真实风险控制，同时尊重用户体验和申诉权利。不能为 KPI 刷指标伤害用户或绕过合规；灰色地带先升级确认，不自行放宽。"

### 12.9 模型系统性偏见/误杀某群体（Q151）

1. **先暂停相关自动决策**（止血）；
2. 定位偏见来源：训练数据、特征、标注还是策略；
3. 抽检影响面、评估危害等级、报告负责人；
4. 修复后做**分层公平性指标**（按群体分桶的准召），灰度上线。

**关键句**："公平性必须和准召一起监控，不能事后补救。"

### 12.10 职业规划（Q152）

**模板**：短期——把大模型后训练、Agent、Harness 能力迁移到商业化机审，成为能独立负责模型运营的工程师；中期——在安全信任领域形成业务判断力，能设计人机协同链路并带小项目；长期——成为既懂模型又懂业务的治理专家。

### 12.11 你为什么适合这个岗位（Q153）

三点：① 有 SFT/DPO/RLHF 和长文本建模的真实经验；② Autono/EasyHarness 直接对应 Agent/Harness 方向；③ 做过审核类项目，理解人机协同与 badcase 闭环。**主动补短板**："商业机审业务经验不足，但方法论可迁移，学习成本低。"
